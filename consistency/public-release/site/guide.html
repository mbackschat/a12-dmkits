Integrate model checks

Checker @VERSION@ · Kotlin/JVM and Kotlin/JS. Supply canonical A12 DocumentModel JSON; read both the verdict and its coverage.

Kotlin / JVM

import io.github.mbackschat.a12.dm.consistency.ModelSource
import io.github.mbackschat.a12.dm.consistency.check
import io.github.mbackschat.a12.dm.consistency.toJson

val report = check(ModelSource(modelJson))
println(report.toJson())

Use dm-consistency with Gradle, or dm-consistency-jvm for Java/Maven. They resolve the same JVM implementation. Java 21 or newer is required. See the repository README for repository and dependency configuration.

JavaScript integration

The showcase bundles the packed JavaScript checker. npm registry publication is not part of this release; the snippets below describe that package's API, not an npm installation command. Kotlin/JS consumers resolve the published Gradle variant.

import { checkModelJson, checkDraftJson } from 'a12-consistency';

const report = JSON.parse(checkModelJson(modelJson));
const draft = JSON.parse(checkDraftJson(
    modelJson,
    '/Storefront/EmailRequiredForPaidOrder',
    'errorCondition',
    '[MissingField] > 0'
));

The functions take and return JSON strings. checkModelJson reports unreadable input through source diagnostics. checkDraftJson compares candidate text with its baseline; it does not save the draft into your model.

Read the report

FieldMeaning
statusINVALID establishes rejection. INCONCLUSIVE does not establish acceptance.
outcomeThe checker's classification. ALL_CHECKS_PASSED is a scoped pass, paired with INCONCLUSIVE.
completeRemains false: the checker has partial coverage.
findingsDeclaration findings, with codes, locations and explanations. Use justifiesRejection rather than severity alone.
diagnosticsSources or declarations the checker could not read. Keep these separate from model findings.
checksCompletedFamilies that ran. A completed family may still have skipped a declaration.
gapsDisclosed limits or skipped checks; not model defects.

A draft report has its own status, introduced/resolved findings, gaps, baseline report and edited report. Its status concerns the introduced findings; an existing baseline defect does not automatically become the draft's defect.

Further integration surfaces

checkEditJson compares two complete model sources. impactOfJson identifies declarations affected by a candidate edit; affected does not mean invalid. snapshotOfJson supports repeated analysis through an immutable handle and source updates. Source JARs accompanying each publication document the corresponding typed Kotlin APIs.

The checker needs neither the Kernel nor the Interpreter at runtime. Full A12 acceptance still belongs to the Kernel; Document evaluation belongs to the Interpreter.
