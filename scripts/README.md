# `scripts/` — release & build tooling

Maintainer scripts for building, packaging, and releasing `dmtool`. Most are not needed for the everyday dev inner loop (that's `./gradlew test` — see the top-level [`README.md`](../README.md)); they drive the **native image**, the **agent plugins**, and the **public release mirror**. The one **dev-loop** exception is [`verify-demos.sh`](verify-demos.sh) — run it before committing any change to a verb's output shape, so the CI-only demo gate can't leave you with silent drift.

| Script | What it does | When to run |
|---|---|---|
| [`sync-plugin-assets.sh`](sync-plugin-assets.sh) | Copy the **single-source** plugin assets — the authoring skill, bug-report skill, installer, and release-asset manifest — into every agent plugin tree (`plugin/`, `plugin-codex/`). `--check` verifies the copies match and fails on drift (CI guard). | After editing a canonical plugin asset; `--check` runs in CI. |
| [`release-assets.sh`](release-assets.sh) | **Data, not run directly.** The canonical public-release binary asset names + platform mapping (`Darwin/arm64`, Linux x64/arm64, Windows x64). Release scripts source it; plugin copies receive it beside the installer. | Edit when adding/removing a shipped binary target. Then update the mirror workflow matrix and run `check-release-assets.sh`. |
| [`check-release-assets.sh`](check-release-assets.sh) | Verify every release surface still agrees with `release-assets.sh`: platform mapping works and the static `.github/mirror-workflows/build-native.yml` asset rows match the manifest. Wrapped by `ReleaseAssetsManifestTest`. | After editing `release-assets.sh` or the mirror workflow; runs in `:test` / CI. |
| [`ensure-dmtool.sh`](ensure-dmtool.sh) | **Canonical on-demand installer** (agent-agnostic): downloads the per-OS native binary from the release mirror, checksum-verifies it, caches it **version-aware** (`bin/<version>/`, stable symlink at `bin/dmtool`), and prints its absolute path. **There is no session hook** — it is synced **into each plugin's skill dir** (beside `SKILL.md`) and the skill runs it the first time `dmtool` is needed. | Don't run directly; edit here, then `sync-plugin-assets.sh`. |
| [`selftest-ensure-dmtool.sh`](selftest-ensure-dmtool.sh) | Behavioral guard for the installer above: stubs a fake release server and asserts the cache is **version-aware** (a `VERSION` bump re-downloads, the same version reuses, old versions prune). Run under the test suite by `EnsureDmtoolCacheTest`. | On any change to `ensure-dmtool.sh`; runs in `:test` / CI. |
| [`verify-demos.sh`](verify-demos.sh) | Build the JVM launcher (installDist) and run **every** `examples/` Showboat demo through `showboat verify`, **in parallel** — exactly the CI drift gate (CI runs this same script), but locally and in one command. The demo set is **discovered** (globs `examples/*.md` with a ```output block), not enumerated, so a new demo is never silently skipped. Cap concurrency with `VERIFY_JOBS` (default 6). | Before committing **any** verb output-shape / behavior / diagnostics change (the demos are otherwise CI-only, so local drift sits unnoticed — it bit us twice). |
| [`perf.sh`](perf.sh) | Run an interpreter **performance sweep** with reliable capture and print only the result lines — `perf.sh <gate\|crossover\|distributed\|scaling\|huge\|js> [counts]`. Writes the full `-i` log to `build/perf-<mode>.log` **raw** (never a live `grep`/`head` pipe — that truncates output via SIGPIPE, the trap that lost a run), then extracts the `[perf]`/`[edge]`/`[jsperf]` lines from the file; one invocation = self-consistent numbers. The `js` mode runs the compiled JS bundle directly on Node (Gradle's JS reporter swallows `println`). | When (re)measuring interpreter performance for a report or regression check; not the everyday inner loop. |
| [`capture-native-config.sh`](capture-native-config.sh) | Run the **JUnit `:cli:test` suite** under the GraalVM tracing agent (`build.gradle`'s `-PrkNativeAgent` mode) to (re)capture the reflection metadata the native build needs — the surface *outside* the rule-based packages below. Coverage **tracks the test suite** (replaces the old curated verb list), so a new shape with a test is captured automatically. | On a verb/catalog/kernel/Jackson change — see [`../docs/NATIVE-IMAGE-GRAALVM.md`](../docs/NATIVE-IMAGE-GRAALVM.md) §5.1. |
| [`native-agent-caller-filter.json`](native-agent-caller-filter.json) | **Data, not run directly.** The tracing-agent **caller filter** for the capture above: drops reflective lookups made by the test harness (JUnit/Gradle) so the metadata doesn't record JUnit's instantiation of the `*Test` classes (which share the `…cli` package, so an access-filter can't separate them by package). | Consumed by `capture-native-config.sh`; edit only if the test-infra package names change. |
| [`gen-native-reflect-metadata.sh`](gen-native-reflect-metadata.sh) | **Rule-based** native reflection metadata: register the two bounded reflective-surface packages wholesale (Jackson POJOs + StringTemplate codegen — §3.4) so coverage is shape-independent, not capture-bound. Writes the committed `rulekit-manual/reachability-metadata.json`. | On a **kernel bump** (re-derives from the new jars), or when the gate finds a reflective gap outside the captured surface — see [`../docs/NATIVE-IMAGE-GRAALVM.md`](../docs/NATIVE-IMAGE-GRAALVM.md) §3.4. |
| [`native-gate.sh`](native-gate.sh) | Verify the built native binary: the showboat demos (byte-match, skips JVM-only) **+ the no-crash battery** below. | Before shipping a native binary. |
| [`native-battery.sh`](native-battery.sh) | **No-crash coverage battery** (docs/NATIVE-IMAGE-GRAALVM.md §3.6): drive a broad derived matrix — every fixture × read/validate verbs + the FieldKind × constraint matrix + invalid conditions per locale — through the native binary, asserting no native-image failure signature. Catches the capture-bound reflection/resource gaps a demo-only gate misses (the v0.1.0/v0.1.1 bugs). | Run by `native-gate.sh`; standalone after any native build / kernel bump. |
| [`gen-scenarios.sh`](gen-scenarios.sh) | Generate the **public-mirror-only** `SCENARIOS.md` — a catalogue of the multi-step *sessions* dmtool is exercised with, scraped from the internal `probe/tasks/` (scenario titles + ordered turn prompts only; **no gold, no probe internals**). Emits to stdout; `assemble-release-repo.sh` redirects it fresh into the release tree, so it is **not committed in the source repo** and can't go stale. `--check` self-validates the generator (extracts ≥1 scenario, nothing internal leaked). | Assembled at release; `--check` runs in CI. |
| [`assemble-release-repo.sh`](assemble-release-repo.sh) | Assemble the public `a12-dmtool-releases` tree: both plugins (Claude at root, Codex under `codex/`) + the EUPL-1.2 compliance bundle copied fresh from the pinned kernel checkout + the mirror's `build-native` Actions workflow (single-sourced in [`.github/mirror-workflows/`](../.github/mirror-workflows/)). | At release, and on a kernel bump (notices change). |
| [`bump-version.sh`](bump-version.sh) | **The scripted version bump** (RELEASE-SPEC §4 step 1): replace the project version across the surfaces no guard catches — `build.gradle`, both plugin manifests, `examples/cli-version.md`'s captured `--version`/`manifest.version` lines, and the installer's `VERSION` pin (re-synced to both plugin copies; the one surface `PluginInstallerVersionTest` *does* guard). Leaves the CHANGELOG *content* and the build/verify/commit/tag to judgment (printed as next steps). | At release, **before** committing + tagging — `bump-version.sh X.Y.Z`. |
| [`publish-release.sh`](publish-release.sh) | **The scripted publish glue** (RELEASE-SPEC §4): builds + gates the mac binary, assembles & **pushes the mirror content** (rsync `--delete` into a fresh clone), creates the draft release, uploads the mac binary, dispatches the Linux/Windows CI (Linux x64 + arm64, Windows x64), and (`--go-live`) verifies all binaries + `SHA256SUMS` then flips `--latest`. Enforces the ordering trap (mac binary uploaded **before** the CI dispatch re-sums). | At release, after the version bump + tag — `publish-release.sh vX.Y.Z`, then `… --go-live` after CI is green. |

## The single-source pattern

The skill and the binary installer are shared **verbatim** by both agent plugins, so they live in exactly one place and are **copy-synced** into each plugin's skill dir (symlinks don't survive the release-mirror push). The per-agent files — each plugin's manifest and Codex's `AGENTS.md` — are maintained in place, never synced. There is **no session hook**: the binary is fetched on demand by the skill the first time `dmtool` is needed. `sync-plugin-assets.sh --check` is the no-drift guard; add a new plugin tree to its `PLUGINS` list when another agent is supported.

Rationale and the full release procedure: [`../docs/RELEASE-SPEC.md`](../docs/RELEASE-SPEC.md). Native-image specifics: [`../docs/NATIVE-IMAGE-GRAALVM.md`](../docs/NATIVE-IMAGE-GRAALVM.md).
