# `scripts/` — release & build tooling

Maintainer scripts for building, packaging, and releasing `dmtool` and the standalone interpreter. Most are not needed for the everyday dev inner loop (that's `./gradlew test` — see the top-level [`README.md`](../README.md)); they drive the **native image**, the **agent plugins**, and the two **public release mirrors**. The dev-loop verification exceptions are [`verify-demos.sh`](verify-demos.sh), which catches demo drift after a verb changes, and [`verify-build-cache.sh`](verify-build-cache.sh), which proves expensive compilation can be reused across clean worktrees.

| Script | What it does | When to run |
|---|---|---|
| [`sync-plugin-assets.sh`](sync-plugin-assets.sh) | Copy the **single-source** plugin assets — the authoring skill, bug-report skill, installer, and release-asset manifest — into every agent plugin tree (`plugin/`, `plugin-codex/`). `--check` verifies the copies match and fails on drift (CI guard). | After editing a canonical plugin asset; `--check` runs in CI. |
| [`release-assets.sh`](release-assets.sh) | **Data, not run directly.** The canonical public-release binary asset names + platform mapping (`Darwin/arm64`, Linux x64/arm64, Windows x64). Release scripts source it; plugin copies receive it beside the installer. | Edit when adding/removing a shipped binary target. Then update the mirror workflow matrix and run `check-release-assets.sh`. |
| [`check-release-assets.sh`](check-release-assets.sh) | Verify every release surface still agrees with `release-assets.sh`: platform mapping works and the static `.github/mirror-workflows/build-native.yml` asset rows match the manifest. Wrapped by `ReleaseAssetsManifestTest`. | After editing `release-assets.sh` or the mirror workflow; runs in `:test` / CI. |
| [`ensure-dmtool.sh`](ensure-dmtool.sh) | **Canonical on-demand installer** (agent-agnostic): downloads the per-OS native binary from the release mirror, checksum-verifies it, caches it **version-aware** (`bin/<version>/`, stable symlink at `bin/dmtool`), and prints its absolute path. **There is no session hook** — it is synced **into each plugin's skill dir** (beside `SKILL.md`) and the skill runs it the first time `dmtool` is needed. | Don't run directly; edit here, then `sync-plugin-assets.sh`. |
| [`selftest-ensure-dmtool.sh`](selftest-ensure-dmtool.sh) | Behavioral guard for the installer above: stubs a fake release server and asserts the cache is **version-aware** (a `VERSION` bump re-downloads, the same version reuses, old versions prune). Run under the test suite by `EnsureDmtoolCacheTest`. | On any change to `ensure-dmtool.sh`; runs in `:test` / CI. |
| [`verify-demos.sh`](verify-demos.sh) | Build the JVM launcher through the worktree-safe [`build.sh`](../build.sh) wrapper, then run **every** `examples/` Showboat demo through `showboat verify`, **in parallel** — exactly the CI drift gate (CI runs this same script), but locally and in one command. The demo set is **discovered** (globs `examples/*.md` with a ```output block), not enumerated, so a new demo is never silently skipped. Cap concurrency with `VERIFY_JOBS` (default 6). **Prerequisite: `node` on PATH** (preflighted, fail-fast) — the `cli-custom-types` JS-worker blocks degrade leniently without it and would read as a false DRIFT. | Before committing **any** verb output-shape / behavior / diagnostics change (the demos are otherwise CI-only, so local drift sits unnoticed — it bit us twice). |
| [`verify-build-cache.sh`](verify-build-cache.sh) | Create two temporary clean worktrees at the current commit, run the expensive interpreter JVM/JS plus adapter test compilation offline in both through one shared isolated Gradle home, and require every named compiler task to restore from the local cache in the second. Elapsed time is printed but deliberately not gated. | After changing Gradle/Kotlin build inputs, cache policy, compiler memory, or task path sensitivity; it requires a clean committed worktree. |
| [`gradle-environment.sh`](gradle-environment.sh) | **Shared helper.** Resolve the init-script-free Gradle user home consistently for the primary checkout, linked worktrees, and isolated release consumers. Consumer homes may reuse its already-resolved wrapper distribution without sharing dependency caches or init scripts. | Sourced by [`build.sh`](../build.sh) and release consumer smokes; do not run directly. |
| [`perf.sh`](perf.sh) | Run the existing interpreter **diagnostic/regression sweeps** with reliable capture and print only the result lines—`perf.sh <gate\|bench\|crossover\|distributed\|scaling\|huge\|js> [pattern-or-counts-or-scenario]`. `gate` runs the routine paired-median growth/canary tier through the dedicated single-fork, non-cacheable `:adapter:perfGateTest` task and accepts a JUnit method pattern; `bench` runs the closed B-series kernel-ratio inventory with dynamic-Groovy/generated-Java agreement and accepts one exact scenario id (`perf.sh bench B9-berlin-datetime`, unknown ids fail). The script writes the full `-i` log to `build/perf-<mode>.log` raw (never a live `grep`/`head` pipe, which truncates via SIGPIPE), then extracts result lines. The `js` mode propagates the Node/Mocha exit after printing the captured result lines, so a failing JS performance run cannot report success (IF170). This remains the diagnostic/catastrophe harness; the separate `interpreter-performance.sh` owns fresh-process and native evidence. | For diagnostic measurements and catastrophic-regression checks; not startup certification or the everyday inner loop. |
| [`interpreter-performance.sh`](interpreter-performance.sh) | Run the complete local IF172 measurement bundle from one **clean commit** and explicit `<runner-id>`: independent fresh JVM/Node first-answer processes, absolute/paired Node and 100k-row JVM warm throughput, the inventory-derived same-run generated-Java ratio report, and parent-clock native `model eval` through complete envelope + exit. The committed B1/B2/48/192-rule models and native instance are generated/freshness-guarded from the typed performance catalog; every sample checks exact supported outcomes. Reports carry commit, runner/runtime/heap, `id@version`, content fingerprint, estimator, sample count, and raw samples. The lane promotes no number and changes no CI schedule. | When collecting reproducible NFR-S/P evidence locally; use the ratified sample count for a certification candidate. |
| [`interpreter-footprint.sh`](interpreter-footprint.sh) | Run the local-only IF162 runtime-footprint lane from a **clean commit** with explicit `<forks>=5+ <base-N> <warmup> <repetitions>`. It launches independent fixed-heap JVM and `--expose-gc` Node workers at `N, 2N, 4N, 8N`, validates every retained/allocation/cache/owner/semantic sample, and writes one structured informative median/curve report. It promotes no threshold and is not wired into CI. | When collecting reproducible NFR-F2 evidence locally; not the everyday test loop. |
| [`interpreter-delivery-footprint.sh`](interpreter-delivery-footprint.sh) | Rebuild the current clean commit and an explicit previous release through one injected protocol-v2 collector; record thin/packed JVM, JS KLIB, native CLI, native-equivalent trimmed-JVM, the real npm tarball, and the clean staged Maven repository bytes/SHA; compile/run the packed-JVM consumer, execute both CLI comparators, and require the npm plus standalone Kotlin/JVM/Kotlin/JS publication consumers. A surface absent from an archived revision is recorded as unavailable with no fake numeric delta. It promotes no threshold and changes no CI schedule. | When collecting reproducible NFR-F1 delivery/ratchet evidence locally. |
| [`capture-native-config.sh`](capture-native-config.sh) | Run the **JUnit `:cli:test` suite** under the GraalVM tracing agent (`build.gradle`'s `-PrkNativeAgent` mode) to (re)capture the reflection metadata the native build needs — the surface *outside* the rule-based packages below. It delegates Gradle startup to the worktree-safe [`build.sh`](../build.sh) wrapper while the traced test JVM comes from `GRAALVM_HOME`. Coverage **tracks the test suite** (replaces the old curated verb list), so a new shape with a test is captured automatically. | On a verb/catalog/kernel/Jackson change — see [`../docs/NATIVE-IMAGE-GRAALVM.md`](../docs/NATIVE-IMAGE-GRAALVM.md) §5.1. |
| [`native-agent-caller-filter.json`](native-agent-caller-filter.json) | **Data, not run directly.** The tracing-agent **caller filter** for the capture above: drops reflective lookups made by the test harness (JUnit/Gradle) so the metadata doesn't record JUnit's instantiation of the `*Test` classes (which share the `…cli` package, so an access-filter can't separate them by package). | Consumed by `capture-native-config.sh`; edit only if the test-infra package names change. |
| [`gen-native-reflect-metadata.sh`](gen-native-reflect-metadata.sh) | **Rule-based** native reflection metadata: register the two bounded reflective-surface packages wholesale (Jackson POJOs + StringTemplate codegen — §3.4) so coverage is shape-independent, not capture-bound. Writes the committed `rulekit-manual/reachability-metadata.json`. | On a **kernel bump** (re-derives from the new jars), or when the gate finds a reflective gap outside the captured surface — see [`../docs/NATIVE-IMAGE-GRAALVM.md`](../docs/NATIVE-IMAGE-GRAALVM.md) §3.4. |
| [`native-gate.sh`](native-gate.sh) | Verify the built native binary: the showboat demos (byte-match, skips JVM-only) **+ the no-crash battery** below. | Before shipping a native binary. |
| [`native-battery.sh`](native-battery.sh) | **No-crash coverage battery** (docs/NATIVE-IMAGE-GRAALVM.md §3.6): drive a broad derived matrix — every fixture × read/validate verbs + the FieldKind × constraint matrix + invalid conditions per locale — through the native binary, asserting no native-image failure signature. Catches the capture-bound reflection/resource gaps a demo-only gate misses (the v0.1.0/v0.1.1 bugs). | Run by `native-gate.sh`; standalone after any native build / kernel bump. |
| [`gen-scenarios.sh`](gen-scenarios.sh) | Generate the **public-mirror-only** `SCENARIOS.md` — a catalogue of the multi-step *sessions* dmtool is exercised with, scraped from the internal `probe/tasks/` (scenario titles + ordered turn prompts only; **no gold, no probe internals**). | [`interpreter-release-assets.sh`](interpreter-release-assets.sh) | **Data, not run directly.** Generate the four version-derived interpreter payload names: npm-compatible tarball, Maven repository, API docs, and showcase. | Edit only when the interpreter release-asset contract changes. |
| [`assemble-interpreter-release-repo.sh`](assemble-interpreter-release-repo.sh) | Assemble the cumulative `a12-interpreter-releases` tree and immutable payload from the already qualified npm, Maven, API-doc, and showcase outputs. | [`check-interpreter-release-repo.sh`](check-interpreter-release-repo.sh) | Verify the interpreter mirror's structural allowlist, secret/path boundary, exact file inventory, and file digests. | After assembly and before any public-mirror commit. |
| [`publish-interpreter-release.sh`](publish-interpreter-release.sh) | Qualify, stage, and promote an interpreter release through the same draft/review/go-live protocol as dmtool. After the bounded `:interpreter:check` command builds the exact source tag, qualification verifies its output and writes a source/tag/checksum-bound receipt. Stage consumes only those unchanged outputs, pushes the workflow bootstrap with the release identity, creates a draft, and dispatches the public rebuild. Go-live verifies authenticated draft content and anonymous Pages, publishes as non-latest, anonymously re-verifies every release asset and runs the standalone Maven/TypeScript consumers, then marks only stable tags latest. A post-publication smoke failure is resumable without weakening the immutable identity checks. | Run `./build.sh --console=plain -PinterpreterReleaseTag=vX.Y.Z :interpreter:check`, then `publish-interpreter-release.sh interpreter-vX.Y.Z --qualify`, then the same publisher command without an operation flag to stage, then repeat with `--go-live` after review. |

| [`interpreter-release-github.sh`](interpreter-release-github.sh) | **Production host backend.** Project the shared publisher operations onto `gh` Releases/Actions/Pages. Before the first deployment it creates a missing Pages site—or updates a legacy one—with the required `workflow` build type. | Sourced automatically outside rehearsal; do not run directly. |
| [`interpreter-release-rehearsal-host.sh`](interpreter-release-rehearsal-host.sh) | **Test host backend.** Project the same publisher operations onto disposable local Git and files. | Sourced only under the explicit rehearsal switch; do not run directly. |
| [`smoke-interpreter-public-release.sh`](smoke-interpreter-public-release.sh) | Execute the existing standalone Kotlin/JVM and TypeScript consumer programs against the anonymous Pages Maven repository and the anonymously downloaded npm-compatible tarball. Uses fresh Gradle/pnpm homes so local project substitution and package caches cannot mask a broken publication, while reusing the source build's already-resolved wrapper distribution to avoid a redundant network fetch. | Called by the production go-live backend after non-latest publication and before a stable release is marked latest. |
| [`release-mirror-common.sh`](release-mirror-common.sh) | **Shared helper.** Supply deterministic digest/inventory and secret/path guards for generated public mirrors. | [`bump-version.sh`](bump-version.sh) | **The scripted version bump** (RELEASE-SPEC §4 step 1): replace the project version across the surfaces no guard catches — `build.gradle`, both plugin manifests, `examples/cli-version.md`'s captured `--version`/`manifest.version` lines, and the installer's `VERSION` pin (re-synced to both plugin copies; the one surface `PluginInstallerVersionTest` *does* guard). ## The single-source pattern

The skill and the binary installer are shared **verbatim** by both agent plugins, so they live in exactly one place and are **copy-synced** into each plugin's skill dir (symlinks don't survive the release-mirror push). The per-agent files — each plugin's manifest and Codex's `AGENTS.md` — are maintained in place, never synced. There is **no session hook**: the binary is fetched on demand by the skill the first time `dmtool` is needed. `sync-plugin-assets.sh --check` is the no-drift guard; add a new plugin tree to its `PLUGINS` list when another agent is supported.

Rationale and the full release procedure: [`../docs/RELEASE-SPEC.md`](../docs/RELEASE-SPEC.md). Native-image specifics: [`../docs/NATIVE-IMAGE-GRAALVM.md`](../docs/NATIVE-IMAGE-GRAALVM.md).
