# Capture-boundary mutation suite

The machine-checkable mutation-sensitivity harnesses for the portable evidence-capture boundary ([`docs/CONFORMANCE-CORPUS-SPEC.md`](../../docs/CONFORMANCE-CORPUS-SPEC.md) §15; the adopted [`A12-DMKITS-CAPTURE-PROPOSAL.md`](../../docs/A12-DMKITS-CAPTURE-PROPOSAL.md) §"Required tests and mutation sensitivity") — two tiers, two receipts: the generic BOUNDARY suite ([`run-mutations.py`](run-mutations.py)) and the SCENARIO-SEMANTIC suite for the external `string-direct-cascade-v1` question ([`run-scenario-mutations.py`](run-scenario-mutations.py)).

**What it does.** For every boundary-applicable mutation from the proposal's list (plus the Set-Z2 audit-correction classes), [`run-mutations.py`](run-mutations.py): records the classified source-tree digest → applies the mutation → runs the PREDICTED narrow guard (a targeted JUnit class/method, the `verifyCapturePurity` lint, or the REAL command in `--development` mode) → asserts it FIRES (a stale guard reference — "No tests found" — fails the suite loudly, never records a fired guard) → restores the exact source bytes → asserts the tree digest returned to its pre-mutation value → appends a receipt entry. Artifact-level mutations run through the real `capture`/`verify`/`validate-scenarios` commands over a disposable `--development` packet in two tiers: the INTEGRITY tier leaves the receipt stale (stray file, symlink, byte drift, removed artifact), the RELATIONAL tier RENEWS the receipt and re-binds envelope digests so only the closed relational validator can refuse the internal contradiction. The run finishes with the natural full capture gate green.

**The receipt.** [`mutation-receipt.json`](mutation-receipt.json) (`capture-mutation-receipt-v1`): per mutation — id, description, mutated files, expected guard, actual failing guard, real-command step where applicable, pre/post tree digests, exact-restoration flag — plus the HEAD revision and the natural-gate result. Mutant packets are disposable and qualification-ineligible by construction (`--development`). This boundary receipt is FROZEN at its accepted **40** mutations (the V1 freeze, spec §15a); Set AB's M26 — a mutation of the rich cell-state mapping that exists only on the rejected Set AB lane — is preserved separately as experimental future-v2 evidence in [`mutation-receipt-experimental-m26-future-v2.json`](mutation-receipt-experimental-m26-future-v2.json), never inside the frozen receipt.

**Run** (from the repo root, CLEAN tree — the mutations must be the only dirt; takes ~15–25 min):

```
python3 adapter/capture-mutations/run-mutations.py
```

## The scenario-semantic suite (Set Z3 → Z4 — the formerly deferred map, executed)

[`run-scenario-mutations.py`](run-scenario-mutations.py) proves the five-case `string-direct-cascade-v1` matrix OBSERVES the scenario semantics (S01–S09: the accepted-equal all-clean/changed-subset split, the source-absent stale-cascade `"OLD-X"`, the rejected-attempted-value-reaching-the-dependent, the *semantic* half of cause reconstruction — attempted value, code, message type, pointer — and the absent-vs-present-empty collapse). Each mutation corrupts one semantic aspect in capture or interpreter source, the REAL `capture --development` runs the exact external pack (bytes pinned by SHA-256 — resolved from `$CASCADE_SCENARIO_JSON` or the sibling `../a12-kernel-lean` checkout, never copied into this repo), and the REAL `diff-packets` against a same-revision reference development packet must report EXACTLY the predicted per-case/per-runner observation drift, pinned further by a structured field assertion. *Receipt lineage:* the Set Z3 receipt [`scenario-mutation-receipt-string-direct-cascade-v1.json`](scenario-mutation-receipt-string-direct-cascade-v1.json) (`capture-scenario-mutation-receipt-v1`) is **rejected version-identity history** — it bound the in-place-mutated capabilities bytes (spec §15a) — and stays committed untouched; the harness now writes the SUCCESSOR receipt [`scenario-mutation-receipt-string-direct-cascade-v1-r2.json`](scenario-mutation-receipt-string-direct-cascade-v1-r2.json) (`capture-scenario-mutation-receipt-v2` — additionally binds the FROZEN capabilities digest, refusing on any other, and carries the explicit `predecessor` reference with its pinned digest). Both bind scenario/model/capabilities hashes, kernel version, the revision under test, commands, per-mutation prediction/actual/restoration, natural gate. The generic boundary receipt is never rewritten by this suite.

```
python3 adapter/capture-mutations/run-scenario-mutations.py
```

The compact legacy corpus signature is guarded by the existing `corpusReplayTest` gate (this program never touched that surface). The full mapping lives in the spec's §15f.
