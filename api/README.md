# Public-API goldens

One committed file per **published** Java artifact, holding every public and protected type and member it exposes. Generated by `PublicApiDumper`; verified by `PublicApiGuardTest`; never hand-edited.

```sh
./build.sh dumpKitApi     # regenerate, then review the diff
./build.sh :apiGuardTest  # verify (CI never runs the fixer)
```

**This is a visibility guard, not a no-break promise.** At `0.x` a public-surface change is *allowed* — what it must not be is accidental. The committed golden is the reviewed truth, the guard fails on any drift, and the author regenerates deliberately so the change lands as a reviewable diff in the same commit. Verifier and fixer share one dump path, so they cannot disagree, and because CI never runs the fixer a forgotten regenerate still fails the build.

**One hard rule rides the same walk:** no third-party type on any published signature. An `implementation`-scoped dependency such as Jackson can therefore never force itself onto a consumer's compile classpath — a whole class of leak made unshippable rather than merely visible.

**A Kotlin note.** `internal` is a Kotlin-compiler boundary, not a JVM one, so an `internal` class is public in bytecode and appears here. Those entries are implementation detail; the golden exists so that movement in them is a reviewed diff rather than an accident.

The multiplatform artifacts are goldened separately, next to their own modules — [`../consistency/api`](../consistency/api) for `dm-consistency`, and [`../interpreter/api`](../interpreter/api) for `dm-interpreter`. Release contract: [`docs/RELEASE-SPEC.md`](../docs/RELEASE-SPEC.md) §11.
