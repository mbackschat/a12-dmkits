# dmkits — API design findings

> The numbered **design-findings** log for the rulekit/modelkit DSL/API — the *why* behind the library's shape: the design decisions, the rejected alternatives, and the non-obvious insights accumulated while building, cited as **"finding N"** across the guide, the specs, and the gap ledgers. Split out of [`API-GUIDE.md`](API-GUIDE.md) (2026-06-16) so the guide stays a user-facing capability narrative.
>
> **This is a rationale record, not a status surface.** *What's built* is shown — and kept honest — by the docs + the gated/derived surfaces: the test-backed [`API-GUIDE.md`](API-GUIDE.md) snippets, the CI-gated [`../examples/`](../examples/) demos, and `manifest` / the conformance matrix (derived from the live code, so they can't drift). This doc keeps only the reasoning, and the numbering is stable so the `finding N` anchors resolve. *(The per-capability ✅ status board, and the dated "implemented / locked-by-test" detail each finding once carried, were dropped 2026-06-19 — that's status, and status lives in git + the docs + the demos. The rationale is the part worth keeping.)*

Each finding has a visible `AFN` identifier and a stable `afN` anchor (for example, [AF67](#af67)); existing "finding N" citations refer to the same numbered finding.

<a id="design-findings"></a>

## AF1: `Dsl.*` is a handles-only static facade; string-path convenience stays on `BoundModel` <a id="af1"></a>

Keeps typo-able path strings out of the immutable AST.

## AF2: Numeric scale metadata is a shared typed summary, not a field/literal syntax exception <a id="af2"></a>

The kernel carries a known signed scale or unknown independently from multiplicative-constant capability, and only a capable smaller-scale equality operand may be padded. The typed surface therefore composes the summary through fields, literals, arithmetic, counts, and rounding; model-derived shapes unavailable at a generic read boundary defer to the live kernel. Carrying that private metadata required `NumberExpr` to become a final value class rather than a record while retaining its constructor/accessor/value equality; record-pattern/reflection consumers are the explicit incompatibility, not something hidden as an additive change.

## AF3: `transform` is a bottom-up, identity-preserving rewriter <a id="af3"></a>

The calculation twin triggers at the first nesting calculation node.

## AF4: Foreign-rule identity is designed *with* the authoring object, not after <a id="af4"></a>

`ExistingRule` (full name + slots + raw text) shares a surface with the `Rule` builder so read and author stay symmetric.

## AF5: Converter gaps are data, not exceptions <a id="af5"></a>

`read` returns a sealed `ReadResult` (`Converted`/`Opaque`); an unmodeled construct is preserved verbatim, never corrupt (F11 "preserve the unknown"). The strict `UnsupportedConstructException` stays the converter's *internal* unwind signal only.

## AF6: One engine, two personas — and only the BA needs a bespoke vehicle. <a id="af6"></a>

A developer uses rulekit as a library in their own project, where the project compiler already supplies compile-first steering; the modeller/BA (can't write Java) gets the CLI. The two imagined vehicles (JBang-for-devs + CLI-for-BAs) collapse to one — the CLI — shrinking blast radius. (PROJECT-DESIGN N10/D16/§14.)

## AF7: `explain` flags suspicions, not just facts <a id="af7"></a>

The lint half of F4a (finding 17): cheap heuristics (inverted predicate, unguarded negative in iteration) over the same projection.

## AF8: A rendered diff discloses its lossiness up front <a id="af8"></a>

What re-rendering drops is part of `RenderedDiff`'s contract (refined by finding 27: the leading `;;` comment is preserved; only inline/trailing comments + non-canonical formatting are lost).

## AF9: The model index is navigated by plain `Stream.filter`, not a query DSL <a id="af9"></a>

`fields()`/`groups()` return rich info handles that narrow to typed authoring handles (`asNum()`/…): lenient exploring, strict authoring (jOOQ's `Field<?>` coercion). No XPath-style matcher API for glob paths or ancestry axes (the jOOQ `Meta` restraint — that complexity is gated on a real consumer, not built speculatively), safe because a `BoundModel` is an immutable snapshot (F0).

## AF10: n-ary `allOf`/`anyOf` are varargs And/Or folds <a id="af10"></a>

Parenthesization falls out of the renderer's mixing rule.

## AF11: Fragment libraries are the re-expression vocabulary <a id="af11"></a>

Modify-by-re-express often means recognizing a *named idiom*, so teams keep a `…Idioms` class and the skill teaches preferring its fragments over raw composition (also the home for org-specific conventions).

## AF12: The model-context surface (F9a) is F9's other half <a id="af12"></a>

The agent enters by a *name*, so `describe`/`find`/`whereUsed` (name resolution + the field→rules inverse) must fire before `explain`. A `BoundModel` is an immutable snapshot (no staleness; writes yield a new binding; lookups memoized internally). The live `describe()` contract is the complete structured field/group catalogue; scoped and depth-limited progressive disclosure belongs to the separate `model report --tree --root … --depth …` surface.

## AF13: Files/stdout are the agent API <a id="af13"></a>

The context surface is greppable JSONL (`fields/groups/rules.jsonl` + a model card); grep is the query language agents already know, dissolving the 10k-field-context and most bespoke-query-API problems. Export-once-then-grep is the taught loop; reference resolution is labeled *in the artifact* (`"resolution":"heuristic"`) to keep agents honest pre-adapter.

## AF14: Constraint mining beats whack-a-mole <a id="af14"></a>

Structural laws sit in enumerable sources (the public accessor lists for slot parity, the `MVK_*` enums → the MVK ledger, the kernel-mm metamodels, the deserializer tier); sweep them rather than tripping over them by accident. (The standing anti-whack-a-mole discipline; CLAUDE.md.)

## AF15: When an increment's probes surface an adjacent kernel law, chase it in the same increment <a id="af15"></a>

It's already reproduced, so the fix + lock are cheapest right there (e.g. the pattern increment also fixed a latent C-style `quote()` bug once it found DSL literals escape by quote-doubling, not backslashes).

## AF16: Compose to extend; `transform` only to operate inside <a id="af16"></a>

`ast.and(more)` keeps intent on the surface; `transform` is the surgical tool (node replacement, placement, bulk rewrites). Reaching for `transform` on a plain extension is machinery over intent. The skill teaches the decision rule ("extending? `and()`. editing inside? `transform`."), not just the APIs.

## AF17: Rich diagnostics are an LLM-facing requirement (F4a) <a id="af17"></a>

Every error *and* warning carries what / where / how-to-fix in one LSP-`Diagnostic`-shaped structure across four origins (PRECHECK / KERNEL / LINT / ENVIRONMENT). Two leverage moves: **catalog-join** (a kernel `MVK_*` inherits the matching catalog entry's `fix`/`gotchas` — curated and drift-free) and **applicable fixes** (the `fix` carries valid replacement DSL, rustc-style, not prose) + "did you mean" off the model index. The distinguishing layer is **LINT/gotcha**: "compiles, kernel-accepts, but probably not what you meant" is something `checkConsistency` can never say.

## AF18: Field-vs-field comparison was a missing basic that unblocked two features <a id="af18"></a>

Cross-field rules (confirmation match, range sanity, reconciliation) *and* `$` correlation. The cheap unlock: string/enum field-vs-field equality has no scale (buildable at once); only *number* field-vs-field needs the D13 scale pre-check. The recordable lesson is **prioritization by what an item unblocks**, not by its own size.

## AF19: Authored-rule span-pointing is a Phase-1 capability (a renderer emit-map), not a Phase-2 read concern <a id="af19"></a>

The renderer already produces the text, so it can record each node's `[start,end)` with no parse; only *foreign*-rule spans truly need read. Build the deeper work (descend into filters/operands, resolve a repeated node) only when a real consumer needs it (an editor/LSP, or the eval) — the consumer-exists discipline, not a blanket buildout.

## AF20: Runtime "fires-on-data" traps belong in the catalog `gotchas`, fed by the RT-semantics drain <a id="af20"></a>

These are neither slot rules (the builder's job) nor accept/reject laws (F4's job) but *judgment* traps: a **valid** condition that misbehaves on data (`Length("")` fires where a bare string comparison stays silent; tolerance doesn't fire at exactly-N; empty-as-0 wins inside `Min`/`Max`; …). The gotcha channel is the formalization vehicle (it rides the self-describing CLI straight into the agent's context — the consumer-exists test holds), and each trap is prime N6 task material.

## AF21: Close a measured cold-agent gap at the surface that owns it — tool first, then catalog, then skill <a id="af21"></a>

Prefer the *tool* self-describing (deterministic, helps even a skill-less agent), fall back to the *catalog* (self-verifying vocabulary), reserve the *skill* for the judgment the other two can't encode. (From the T13 baseline miss: the bracketed-call-args trap → a catalog gotcha + a sharpened skill rule; the missing-per-locale-message gap → `config read` / `model describe` now expose the declared `header.locales` that drive the requirement.)

## AF22: The kernel is the authority on version compatibility; rulekit only classifies <a id="af22"></a>

The build's versions are self-describing (`--version` / `manifest.version`); for an off-version model the kernel decides (accepts older same-major, fail-fasts on newer/different-major), and rulekit classifies that verdict into stable codes (`RK_MODEL_VERSION_SKEW` vs `…_INCOMPATIBLE`). Inform, don't second-guess the kernel; write-back never bumps the version.

## AF23: Refs (to fields *and* groups) are the currency across both kits; L2b codegen is dropped, not parked <a id="af23"></a>

A value ref for any element (existing or just-created) used everywhere (rule scope / error-field / operands + structure-edit targets), with a thin session-bound *editor* as the *one* fluent idiom. The safety invariant: the immutable AST holds **only** pure refs, never the session-carrying editor (functional core / effects at the edge). Codegen is structurally incapable of the runtime create→reference flow (it lags the live edit); a live-node graph's one unique win (rename-tracking) fights the immutable-snapshot grain. (PROJECT-DESIGN D7; naming → §18.7.)

## AF24: Document-part builders fall out of the editor — no new machinery <a id="af24"></a>

Once the editor takes a "where to build" handle and returns refs, a `(GroupEditor, params) → structure + rules` function composes exactly like a rule fragment (finding 11). Whether a team keeps a `Money`/`Address`/`LineItems` library is their call; the claim is only that nothing extra is needed.

## AF25: Includes + type-defs make rulekit a multi-model tool <a id="af25"></a>

Rules author over mounted fields by their mount-name path exactly like local ones; the kernel-free `ModelReader` expands through a `ModelResolver`, imports effective typedefs, and normalizes name-path ids, while the optional backend supplies the consistency verdict. An include mount is a reference-aware **MOVE**, not text substitution: included rules and computations are bound in their pre-mount context, element references are remapped to the mounted name path, and literals/comments stay untouched. Write-back retains the authored source JSON and therefore keeps the include as a `modelAlias` reference (**never inlined** — F6/D9). An included model's own rules travel with it unless the mount excludes them.

## AF26: "Does this rule actually fire?" is a first-class capability, and unsupported evaluation must never look clean <a id="af26"></a>

`evaluate`/`compute` run the model over a document instance and return fired codes / computed values; verify-**by-execution** (run a passing + a violating doc and compare fired codes) is the angle that exposes an inverted-but-kernel-valid rule, and the engine behind the eval's execution-based equivalence judge. The standalone interpreter's `validate` returns both messages and unsupported constructs; its messages-only `validateFull` fails loudly when unsupported is non-empty, so a convenience projection cannot silently turn incomplete coverage into a clean result (IF139). Differential evidence treats the kernel's Groovy-dynamic service as the normative observation anchor; static-Java is co-evidence that detects strategy splits, and a legal split is characterized rather than adopted as interpreter behavior (IF136).

## AF27: `;;` comments are preserved via a node-identity side-channel, not new AST nodes <a id="af27"></a>

The kernel drops comments from its parsed AST, so a side-channel (`Comments`, keyed by node identity) gets the common (leading-comment) case for a fraction of the blast radius of 15 new node types + their switch rewrites. Lessons: a side-channel keyed by identity is the cheap way to attach metadata to an immutable AST you don't want to re-shape, and the *author* and *preserve* halves split cleanly into separate increments.

## AF28: Gates over checklists <a id="af28"></a>

Anything an LLM can skip *will* eventually be skipped, so a criterion that matters becomes a build-failing gate derived from the live artifact, not a checklist item. (Its full realization — the CLI self-describe/diagnose conformance harness — is a CLI-tool concern in [`CLI-CONFORMANCE-SPEC`](./CLI-CONFORMANCE-SPEC.md), not this DSL/API study.)

## AF29: The catalog names each predicate's negation partner (`opposite`) <a id="af29"></a>

The kernel has no generic `Not(…)`, so the inverse of a predicate is *another* predicate; the pairing turns the "no generic negation" trap into a one-hop lookup. A discoverability pointer, not a strict-complement claim (three-valued / formal-error semantics mean `FieldFilled`/`FieldNotFilled` aren't exhaustive). (FEATURE-GAPS G3.)

## AF30: A rule's legal error field is computable up front <a id="af30"></a>

It must be referenced by the condition and inside its iteration scope, so `errorFieldCandidates` turns the `MVK_ERROR_FIELD_NOT_REFERENCED` reject→fix loop into an up-front pick. Two notes worth keeping: a set-based overload fed by the kernel's own `getDirectlyReferencedEntities` is robust where the rulekit converter NPEs on an inconsistent candidate, and that required a *lenient bind* (expand without the consistency gate) — a read-only capability the write path must never use. (FEATURE-GAPS G4.)

## AF31: Two computation laws are caught by a text-level lint before the kernel round-trip <a id="af31"></a>

A precondition can't use `CustomCondition`/`RepetitionNotUnique`, and alternatives must be mutually exclusive. Computation takes the first holding alternative in declaration order, but implicit validation retains every holding mismatch; a duplicate precondition therefore cannot supply the later value yet can still make validation fire. Matched as operator calls by EN+DE keywords; true logical disjointness needs a solver and is out of scope — the exact-duplicate case is the one that always means a bug. (FEATURE-GAPS G5; runtime distinction IF175.)

## AF32: Recurring validation idioms are a typed-DSL-backed catalogue, correct by construction <a id="af32"></a>

Each `patterns` idiom builds its condition through the typed DSL with violation polarity + a referenced error field baked in (the two traps otherwise re-risked each time). Built-ins are typed behind a `PatternEntry` interface a future data-template extension plugs into additively; a no-rot gate kernel-validates every example in CI. (FEATURE-GAPS G2.)

## AF33: A `java.time` overload removes the last format-coupled string from the typed DSL <a id="af33"></a>

`dateValue(LocalDate)`/`timeValue(LocalTime)` render to the kernel's German form and can't be malformed; the `String` overload stays for the CLI/spec path where values legitimately arrive as text. (DEV-API-GAPS DG4.)

## AF34: Computations get the same tooling shape as rules — no sibling asymmetry <a id="af34"></a>

A `ComputationDiagnostics.diagnose` peer, `Computation.Builder.build()` throwing a structured `PrecheckException` (still an `IllegalStateException`, so existing catches hold), and `ReadComputation.Opaque` carrying `canonicalText`. (DEV-API-GAPS DG2.)

## AF35: Explanation projections emit a self-describing `UNKNOWN`, never a cryptic `"?"` <a id="af35"></a>

The computed-field kind comes from the typed `FieldRef` (which always carries a `ValueKind`) rather than a path re-lookup that could miss. (The narrow slice of DG5; the (de)serialization-boundary result records stay `String` by design.)

## AF36: Editing a model reads like authoring it <a id="af36"></a>

The per-type field builders (`numberField`/`enumField`/…) live on the editor, and both routes assemble through a single `FieldAttrs.toField(name)`, so a field added while editing is byte-identical to one built from scratch and a metadata call in the lambda can't be silently dropped. (DEV-API-GAPS DG1.)

## AF37: The navigation surface reads the annotations it can write <a id="af37"></a>

`FieldInfo`/`GroupInfo.annotations()`/`annotation(name)` (read back through the kernel), making "find every field carrying annotation X, then act" a plain stream filter. Fires finding 9's annotation-query trigger with the *minimum* — a per-element read, not a model-wide annotation index.

## AF38: Composition + presence quantifiers take a `List`, not just varargs <a id="af38"></a>

So a rule assembled from a loop/stream folds cleanly (`allOf(List)`/`anyOf(List)` + list overloads of the presence quantifiers); the primitive the bulk/generated-authoring case (the §3.6 mirroring study) was missing.

## AF39: The most-repeated mirroring idiom ships as `a.agreesWith(b)` <a id="af39"></a>

Renders "both filled and equal, or both empty," so its polarity is reviewed *once* instead of per pair; with `allOf(List)` (38) a 7-field address mirror becomes a one-liner.

## AF40: A combinator can be written against a *root group* and applied to any subtree <a id="af40"></a>

`GroupInfo` gained relative navigation (`app.str("Schedule/Name")`), the read peer of the editor's, so a rule like `scheduleConsistency(GroupInfo)` is location-independent (applies to a mounted/included sub-form). It lives on `GroupInfo` (model-aware), not `GroupRef` (a pure value — the §5c AST invariant).

## AF41: The write/edit not-found paths speak the same coded `Diagnostic` as validate/lint <a id="af41"></a>

A reusable `PrecheckException.notFound(RkCode, path)` (`RK_NO_SUCH_RULE`/…) adopted by `ModelWriter`/`KernelAdapter`; additive (still an `IllegalStateException`). Boundary by design: `modelkit`/`core` not-found stay bare — the ⊥/layering invariants forbid them importing `Diagnostic`. (DEV-API-GAPS DG3.)

## AF42: The operator catalog can be browsed, not just looked up by id <a id="af42"></a>

`byKeyword`/`byKind`/`byReturns`; the catalog exists to be discovered.

## AF43: A kernel-free `ModelResolver` SAM keeps multi-model loading off `com.mgmtp.a12.kernel.*` <a id="af43"></a>

`id → DM-JSON`, bridged to the kernel resolver, so the app resolves includes/imports from its own store (a map, a service).

## AF44: `includeLevel` is authorable and a transitive include is distinguished on read <a id="af44"></a>

`MountOptions.single().asModelRoot()` emits the group `includeLevel` (SINGLE_RG omitted = the kernel default); `includes()` is exact, `transitiveIncludes()` reads kernel-added references separately. (DEV-API-GAPS DG6.)

## AF45: `ModelContext.find` returns a typed `ValueKind`, not a stringly `kind` <a id="af45"></a>

Consistency with `FieldInfo.kind()`. (The clean slice of DG5; the wire-boundary result records intentionally stay `String`.)

## AF46: A custom-typed field gets its own string-shaped handle, not a loosened `str()` <a id="af46"></a>

`BoundModel.custom(path)` returns a `StringRef` (kind-checking `== CUSTOM`), so a custom field's text value can be compared (`[Code] == "x"`, legal kernel grammar) through the full `StringRef` surface. The alternative — letting `str()` accept a `CUSTOM` field — was rejected to keep the *one-accessor-per-kind* invariant: each typed accessor still maps to exactly one `ValueKind`, and `str()` stays STRING-only. (DEV-API-GAPS DG13.) The F10 **read** direction matches: the converter's `fieldValueComparison` routes a `CUSTOM` field through the string machinery (`model.custom(path)`), so a stored custom-field comparison reads back typed (`adapter.CustomFieldComparisonReadTest`).

**Computation boundary, measured 2026-10-12:** STRING and CUSTOM share direct-read, literal and concatenation assignments. Exact-kind matching in `Computation.Builder` wrongly refused cross-kind text assignments; inbound concatenation additionally dispatched only STRING targets and requested the STRING-only accessor for CUSTOM leaves. The builder now admits that text family and the converter preserves the original leaf kind through `fieldValueCalculation`. `TextComputationAdmissionReadTest` independently checks thirteen kernel admission rows and ten legal read/rebuild/write cycles; NUMBER-to-text and concatenation-to-Enumeration remain refused. This static admission result does not claim runtime custom-validator behavior.

## AF47: The builder enforces a kernel co-requirement fail-fast, with our own message <a id="af47"></a>

`StringFieldBuilder.noValueValidation()` authors the value-skip flag, and `FieldTypeSpec.StringSpec` rejects the kernel-illegal pair (`noValueValidation` without line breaks, `MVK_STRING_TYPE_NO_VAL_AND_NO_LINE_BREAK`) at `build()` with a named cause — instead of letting it surface as a late kernel reject on load. Mirrors the existing pattern⟺message co-requirement check, so co-requirements caught before the kernel stay consistent. (DEV-API-GAPS DG14; the kernel fact is KERNEL-FINDINGS "STRING `noValueValidation`".)

## AF48: Arithmetic rendering is precedence-aware, so a precedence-overriding group is authorable without a group node <a id="af48"></a>

`DslRenderer` braces a child operand that binds *looser* than its parent, so `times(plus(1, 1))` renders `[BQ] * { 1 + 1 }` (the `{…}` binds before the `*`); arithmetic whose grouping already matches natural precedence (`^` > `*`/`/` > `+`/`-`) stays brace-free and round-trips. No explicit `Dsl.group(…)` node was needed — the renderer derives the braces from the tree. (DEV-API-GAPS DG7.)

## AF49: Temporal arithmetic returns a date-time, and the extractors accept any datetime operand <a id="af49"></a>

`addHours`/`addMinutes`/`addSeconds` return a `DateTimeExpr` (a sub-day shift *is* a date-time, matching `DateShift.Unit`'s declared kind — correcting a latent kind mismatch), and `dateFromDateTime`/`timeFromDateTime` accept any `DateTimeOperand` (a field, a `DateTime(date, time)` construction, *or* a shift), so `DateFromDateTime(AddHours(dt, 5))` composes through the typed surface. (DEV-API-GAPS DG9.)

## AF50: Field references are first-class operands, not only literals, in value lists and semantic indexes <a id="af50"></a>

`StringRef.in(StringRef…)` / `NumberRef.in(NumberRef…)` author a value-list whose entries are `[field]` references (`FieldValueIncludedInValueList(Quantity, [BackorderQuantity])`), and `NumberRef.forIndex(FieldRef)` authors a field-keyed semantic index (`[Count For Sku]`, the lookup key being another field's value) — matching the kernel forms that previously had no typed builder. (DEV-API-GAPS DG8/DG10.)

## AF51: A repeatable group's row sort fields are authorable, gated on the same two preconditions as the index field <a id="af51"></a>

`GroupBuilder.sortField(child, ASC/DESC)` (called repeatedly for a multi-key sort, keys applied in declaration order) emits the kernel's `sortFields` and rejects at `build()` a non-repeatable group or a non-child field, exactly like `indexField`. It is **display/USB-only**: the kernel does not reorder rows for validate/compute, so this is an authoring + read-fidelity capability, not an evaluation one (the interpreter ignores sort order — INTERPRETER-FINDINGS IF22). Verified by a kernel read-back (`getSortFields()`), since the silent-ignore deserializer hides an unhonored key. The CLI surfaces the same edit — `group modify --sort-field <child>[:asc|desc]` / `--clear-sort-fields`, `group read` echoes `sortFields`, and the `apply` group-modify op carries the same keys (shared `SortFieldArg` parser). (FEATURE-GAPS G28.)

## AF52: `Dsl` is a flat factory by design — for a coding agent the discovery surface is the catalog + naming, not the class shape <a id="af52"></a>

An agent discovers an operator by *querying the operator catalog* (`OperatorCatalog`/`operators`) and grepping examples, not by browsing IDE autocomplete the way a human does. So the ~130 `Dsl.*` factory methods stay **flat**: one import, greppable, unambiguous (`Dsl.addYears` — no "which sub-facade?" hop), and a single surface (no flat-vs-faceted "two ways"). Sub-facades (`Dsl.dates().…`) would aid a human's autocomplete but cost an agent an indirection + a wrong-guess surface + a dual API — a *net* debt, so they're a **non-goal**. The discovery levers that serve both consumers are consistent verb-prefix **naming** and the catalog. Re-open only if `Dsl` becomes *incohesive* (mixes concerns beyond "construct a DSL node"). (DEV-API-GAPS, the `Dsl`-grouping item, resolved as out-of-scope.)

## AF53: The constraint read-back surface mirrors the authoring surface — typed accessors, never raw-block navigation <a id="af53"></a>

`ModelDocument` reads back every constraint the per-kind builders write: `fieldPattern` / `fieldMinLength` / `fieldMaxLength` / `fieldMinValue` / `fieldMaxValue` / `fieldMaxFractionalDigits` (the peers of `enumValues`), plus the typeDefinition peers (`typeDefinitionPattern` / …) — needed because a typedef-typed field's own `fieldConfig` is *empty* (its constraints live on the typeDefinition, not the field). A consumer reads a declared constraint without knowing the schema-block quirks (number bounds are *text* under a `number` sub-block; lengths/pattern under `string`; the kernel always carries a scale, defaulting to 0 — KERNEL-FINDINGS). Surfaced by the JSON-Schema exporter, which now reads constraints *exclusively* through these accessors — the dogfood loop closing: the friction of raw-block (`findValue`) navigation drove the API, and the motivating consumer uses it (no `findValue`, no per-block `copyInt`/`copyNumber`). (DEV-API-GAPS, the read-back-accessors item, resolved.)

## AF54: `FieldInfo` carries the declared bounds — the kernel-model peer of finding 53's JSON-tree read-back <a id="af54"></a>

The `Info` "describe it, to explore" surface now reads the field's *declared value constraints*, not just `kind`/`scale`/`annotations`: `FieldInfo.numberMin()`/`numberMax()` (`Optional<BigDecimal>`), `minLength()`/`maxLength()` (`OptionalInt`), `pattern()` (`Optional<String>`), each empty when the kind doesn't carry it — so any field can be probed without a kind check. It is a distinct surface from finding 53's `ModelDocument` accessors *by necessity*: `ModelDocument` reads the **raw DM-JSON tree** (modelkit, the editor substrate), while `FieldInfo` reads the **kernel-typed model** via `ModelIndex` (`numberMin`/`stringPattern`/…, the peers of the existing `numberScale`/`enumValues`) — and because `rulekit ⊥ modelkit`, a rulekit consumer (`ModelContext`, `BoundModel`) cannot borrow the modelkit one. The motivating consumer was `model describe`, which could show `kind`/`scale`/enum-domain but not bounds; it now cards them (`describe.schema` declares `min`/`max`/`minLength`/`maxLength`/`pattern`). Dogfood loop: the gap *was* the bug — fixed in the library (extend `ModelIndex` + `FieldInfo`), never by reading raw DM-JSON in the CLI.

## AF55: A semantic index `[Field For key]` works on ANY comparable field kind, both key forms — not number-only (DG15) <a id="af55"></a>

The kernel places no kind restriction on the indexed field (its flagship example `[Addresses/Country For PreferredAddress]` is an enum), so `forIndex(String)` (constant key) and `forIndex(FieldRef)` (field key, DG8) live on `NumberRef`/`StringRef`/`EnumRef`/`DateRef`/`TimeRef`/`DateTimeRef` alike, each returning that kind's `Expr` (`SemanticIndexValue`/`SemanticIndexFieldValue` are kind-generic — `.kind() = field.kind()`). Read matches: the converter's `fieldValueComparison` builds the semantic node once and dispatches by the indexed field's *kind* to that kind's comparison machinery (a new `enumExprComparison` peer; `EnumExpr` gained the `is`/`isNot` surface `StringExpr` already had). Surfaced by a real-world corpus read (was the residual after the number/field-keyed forms shipped). The `$`-correlated semantic index stays kernel-delegated. (DEV-API-GAPS DG15.) (Catalog: the `SemanticIndex` operator entry now states any-kind + both key forms.)

## AF56: A group carries a per-locale display `label`, authored uniformly with a field's (DG17) <a id="af56"></a>

## AF121: The operand type is what decides whether a kernel-legal shape is authorable at all — and the answer came from measuring the operator, not from reading one example. <a id="af121"></a>

## AF180: A key-selected cell is a `ValueAsDate` source and a `Date` component. <a id="af180"></a>

A12 admits `ValueAsDate(Rows/F For key, …)` and a keyed day, month or year in `Date(…)` from outside the repetition ([KF531](KERNEL-FINDINGS.md#kf531)), and the typed surface could author neither. `ValueAsDate` now holds a sealed `ValueAsDate.Source`, which `FieldRef` and `IndexedFieldValue` implement, so the record names exactly the two operand shapes A12 resolves to one field and nothing else; its accessor is `source()`, where it was `field()`. `SemanticIndex` is a `TemporalComponent`, rendering as the keyed cell it selects, in every `Date` and `Time` slot; day, month, year and hour are measured, and the slot's declaration gate judges the field the key selects in. `BoundModel.valueAsDateFirstDay(SemanticIndex)` and its `LastDay` peer apply the same partial-precision check to the selected field as the unkeyed overloads do, which A12 measures the same way (`MVK_INVALID_DATE_TYPE_FOR_OP` for a keyed full-precision date). The adapter and the interpreter bridge read both keyed shapes back with the key kept. Locked by `validate.laws.KeyedTemporalOperandLawsTest` and `adapter.KeyedTemporalOperandReadTest`.

## AF181: A `$` marker survives every node a marked reference builds, the renderer and the reader. <a id="af181"></a>

Inside a filter, a `$`-marked field reads the rule's own row rather than the candidate's, and a dropped marker still renders a valid reference, so the rule silently compares each candidate with itself. The marker had three homes that disagreed: `FieldRef.correlated`, the `outer` flag of `FieldValue` and `EnumCategoryAccess`, and a separate flag on each typed reference (`NumberRef`, `StringRef`, `EnumRef`, the temporal refs, `CategoryRef`). A typed reference built its nodes from its unmarked field, so `code.outer().in(…)`, `.matches(…)`, `.length()`, `.filled()`, `.asString()`, `.agreesWith(…)` and the rounding factories all lost it, and `FieldRef.outer().value()` and the reader's value read were two spellings of one node. Each record's compact constructor now fixes one home through `FieldRef.marked`: a typed reference keeps the marker on its field, so every node built from that field carries it, while a value node (`FieldValue`, `EnumCategoryAccess`) and a repetition list (`FieldListRef`) keep it on their own flag, the form the reader builds. The renderer writes a single field operand's marker through one helper and a value node's or list's from its flag. The reader keeps the marker on the plain-field operations, a value-list subject and field entry, a `Length` operand, concatenation parts, an arithmetic operand, a group-list member and a `Date` component, and reads one marked field as a presence, as it already read an unmarked one. A12 admits the marker in all of these slots and reads the rule's row in each ([KF534](KERNEL-FINDINGS.md#kf534)); the reader's marker-count guard had been the only thing that noticed, and it could only refuse the whole rule. Locked by `rulekit.dsl.CorrelatedTypedRefMarkerTest`, `adapter.CorrelatedFieldOperandReadTest`, `adapter.CorrelatedTypedRefReadTest`, `adapter.laws.CorrelatedFieldOperandDiffTest` and `adapter.laws.CorrelatedTypedRefSlotDiffTest`.

## AF182: A `Date`/`Time` component outside A12's grammar is refused when the construction is built, in A12's order. <a id="af182"></a>

`TemporalComponent`'s numeric-expression arm exists for the extractors and the number literal, but it accepted any `NumberExpr`, so `Dsl.time(Dsl.maxValue(...))` or `Dsl.time(hour.plus(1))` built and only the kernel refused it. A12's grammar admits a field, a keyed cell, a quoted constant or an extract operation as a component, and draws `MVK_UNEXPECTED_TOKEN` for any other operation in every slot of both constructions ([KF532](KERNEL-FINDINGS.md#kf532)). `TemporalComponentGrammar` answers that with one exhaustive switch over `Calculation`, and both constructions ask it of every component before any slot's extractor check, because A12 does: a parse error answers first in both text orders. A stamp-splitting extract operation is grammatical, so it is each slot's refusal, `MVK_DATE_OR_TIME_EXTRACT_OP_NOT_ALLOWED`, or the four-component form's own class in its century and short year. Every typed literal stays admitted, since the renderer writes it as the quoted constant A12 admits. The bare number is the one class only condition text carries, so the interpreter bridge refuses it itself, asking each component of the text in order through the same public check: whole digits are `MVK_INVALID_ENTITY`, a sign or a decimal point `MVK_UNEXPECTED_TOKEN`. On the read path the kernel parses no such condition, so a stored refused rule reads back as its unparsed text rather than reaching the check. Locked by `rulekit.dsl.TemporalComponentGrammarTest`, `bridge.FunctionsTest.aBareNumberComponentIsRejectedInEveryConstruction`, `adapter.RefusedTemporalComponentReadTest` and `adapter.laws.CheckerConstructorComponentAgreementTest`.


## AF183: Serialized Documents and raw-value authoring use distinct kernel ingress. <a id="af183"></a>

A nested Map matches the shape of A12 Document JSON but does not reproduce its read behavior. `KernelAdapter`'s Map route creates V1 fields from raw strings, so JSON decoded into that route bypasses the model-driven conversion that, for example, pads native `5` to a field's minimum scale. Additive String overloads on `evaluate`, `evaluateApplied`, both `testRule` forms and `compute` use A12's own DocumentV2 serializer; the Map overloads remain the raw authoring contract. One canonical reader serves all JSON methods, and scoped verdict and computation-result projection stay shared. This prevents a test oracle from reporting a conversion error that a real A12 Document would not produce. `KernelAdapterCanonicalDocumentTest` locks canonical owner-reader parity and raw compatibility; `KernelEvalCanonicalIngressTest` protects the CLI test harness. See [API-GUIDE §5e](API-GUIDE.md#5e-run-rules-against-data--does-it-actually-fire-runtime-evaluation).


## AF184: Indexed message helpers reuse typed keys and the kernel's short-name boundary (2026-10-12). <a id="af184"></a>

Message authors previously had to assemble keyed repetition and index-value/category tokens by hand. `Dsl.repetitionIndex(IndexedGroupValue)` reuses the existing keyed operand and renderer; `indexValue(FieldRef)` and `indexCategory(CategoryRef)` render the kernel's quoted short-name syntax rather than an absolute path. These helpers add no domain type or admission refusal: the kernel and portable checker still judge each token against its rule. `MessageInterpolationTest.indexedMessageHelpersReuseTypedKeysAndIndexFieldNames` locks escaping and typed authoring; [KF546](KERNEL-FINDINGS.md#kf546) records the admission and runtime controls.
