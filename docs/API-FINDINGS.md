# dmkits — API design findings

> The numbered **design-findings** log for the rulekit/modelkit DSL/API — the *why* behind the library's shape: the design decisions, the rejected alternatives, and the non-obvious insights accumulated while building, cited as **"finding N"** across the guide, the specs, and the gap ledgers. Split out of [`API-GUIDE.md`](API-GUIDE.md) (2026-06-16) so the guide stays a user-facing capability narrative.
>
> **This is a rationale record, not a status surface.** *What's built* is shown — and kept honest — by the docs + the gated/derived surfaces: the test-backed [`API-GUIDE.md`](API-GUIDE.md) snippets, the CI-gated [`../examples/`](../examples/) demos, and `manifest` / the conformance matrix (derived from the live code, so they can't drift). This doc keeps only the reasoning, and the numbering is stable so the `finding N` anchors resolve. *(The per-capability ✅ status board, and the dated "implemented / locked-by-test" detail each finding once carried, were dropped 2026-06-19 — that's status, and status lives in git + the docs + the demos. The rationale is the part worth keeping.)*

## Design findings

1. **`Dsl.*` is a handles-only static facade; string-path convenience stays on `BoundModel`** — keeps typo-able path strings out of the immutable AST.
2. **Scale-aware literal overloads are rendering-fidelity, not a pre-check** — the kernel's decimal-scale check is *field-vs-field only*; literals are exempt (D13's pre-check is reserved for field-operand comparisons).
3. **`transform` is a bottom-up, identity-preserving rewriter** — the calculation twin triggers at the first nesting calculation node.
4. **Foreign-rule identity is designed *with* the authoring object, not after** — `ExistingRule` (full name + slots + raw text) shares a surface with the `Rule` builder so read and author stay symmetric.
5. **Converter gaps are data, not exceptions** — `read` returns a sealed `ReadResult` (`Converted`/`Opaque`); an unmodeled construct is preserved verbatim, never corrupt (F11 "preserve the unknown"). The strict `UnsupportedConstructException` stays the converter's *internal* unwind signal only.
6. **One engine, two personas — and only the BA needs a bespoke vehicle.** A developer uses rulekit as a library in their own project, where the project compiler already supplies compile-first steering; the modeller/BA (can't write Java) gets the CLI. The two imagined vehicles (JBang-for-devs + CLI-for-BAs) collapse to one — the CLI — shrinking blast radius. (PROJECT-DESIGN N10/D16/§14.)
7. **`explain` flags suspicions, not just facts** — the lint half of F4a (finding 17): cheap heuristics (inverted predicate, unguarded negative in iteration) over the same projection.
8. **A rendered diff discloses its lossiness up front** — what re-rendering drops is part of `RenderedDiff`'s contract (refined by finding 27: the leading `;;` comment is preserved; only inline/trailing comments + non-canonical formatting are lost).
9. **The model index is navigated by plain `Stream.filter`, not a query DSL** — `fields()`/`groups()` return rich info handles that narrow to typed authoring handles (`asNum()`/…): lenient exploring, strict authoring (jOOQ's `Field<?>` coercion). No XPath-style matcher API for glob paths or ancestry axes (the jOOQ `Meta` restraint — that complexity is gated on a real consumer, not built speculatively), safe because a `BoundModel` is an immutable snapshot (F0).
10. **n-ary `allOf`/`anyOf` are varargs And/Or folds** — parenthesization falls out of the renderer's mixing rule.
11. **Fragment libraries are the re-expression vocabulary** — modify-by-re-express often means recognizing a *named idiom*, so teams keep a `…Idioms` class and the skill teaches preferring its fragments over raw composition (also the home for org-specific conventions).
12. **The model-context surface (F9a) is F9's other half** — the agent enters by a *name*, so `describe`/`find`/`whereUsed` (name resolution + the field→rules inverse) must fire before `explain`. Two governing constraints: a `BoundModel` is an immutable snapshot (no staleness; writes yield a new binding; lookups memoized internally), and `describe()` is progressive disclosure (a 10k-field DM exists), never a full catalogue.
13. **Files/stdout are the agent API** — the context surface is greppable JSONL (`fields/groups/rules.jsonl` + a model card); grep is the query language agents already know, dissolving the 10k-field-context and most bespoke-query-API problems. Export-once-then-grep is the taught loop; reference resolution is labeled *in the artifact* (`"resolution":"heuristic"`) to keep agents honest pre-adapter.
14. **Constraint mining beats whack-a-mole** — structural laws sit in enumerable sources (the public accessor lists for slot parity, the `MVK_*` enums → the MVK ledger, the kernel-mm metamodels, the deserializer tier); sweep them rather than tripping over them by accident. (The standing anti-whack-a-mole discipline; CLAUDE.md.)
15. **When an increment's probes surface an adjacent kernel law, chase it in the same increment** — it's already reproduced, so the fix + lock are cheapest right there (e.g. the pattern increment also fixed a latent C-style `quote()` bug once it found DSL literals escape by quote-doubling, not backslashes).
16. **Compose to extend; `transform` only to operate inside** — `ast.and(more)` keeps intent on the surface; `transform` is the surgical tool (node replacement, placement, bulk rewrites). Reaching for `transform` on a plain extension is machinery over intent. The skill teaches the decision rule ("extending? `and()`. editing inside? `transform`."), not just the APIs.
17. **Rich diagnostics are an LLM-facing requirement (F4a)** — every error *and* warning carries what / where / how-to-fix in one LSP-`Diagnostic`-shaped structure across four origins (PRECHECK / KERNEL / LINT / ENVIRONMENT). Two leverage moves: **catalog-join** (a kernel `MVK_*` inherits the matching catalog entry's `fix`/`gotchas` — curated and drift-free) and **applicable fixes** (the `fix` carries valid replacement DSL, rustc-style, not prose) + "did you mean" off the model index. The distinguishing layer is **LINT/gotcha**: "compiles, kernel-accepts, but probably not what you meant" is something `checkConsistency` can never say.
18. **Field-vs-field comparison was a missing basic that unblocked two features** — cross-field rules (confirmation match, range sanity, reconciliation) *and* `$` correlation. The cheap unlock: string/enum field-vs-field equality has no scale (buildable at once); only *number* field-vs-field needs the D13 scale pre-check. The recordable lesson is **prioritization by what an item unblocks**, not by its own size.
19. **Authored-rule span-pointing is a Phase-1 capability (a renderer emit-map), not a Phase-2 read concern** — the renderer already produces the text, so it can record each node's `[start,end)` with no parse; only *foreign*-rule spans truly need read. Build the deeper work (descend into filters/operands, resolve a repeated node) only when a real consumer needs it (an editor/LSP, or the eval) — the consumer-exists discipline, not a blanket buildout.
20. **Runtime "fires-on-data" traps belong in the catalog `gotchas`, fed by the RT-semantics drain** — these are neither slot rules (the builder's job) nor accept/reject laws (F4's job) but *judgment* traps: a **valid** condition that misbehaves on data (`Length("")` fires where a bare string comparison stays silent; tolerance doesn't fire at exactly-N; empty-as-0 wins inside `Min`/`Max`; …). The gotcha channel is the formalization vehicle (it rides the self-describing CLI straight into the agent's context — the consumer-exists test holds), and each trap is prime N6 task material.
21. **Close a measured cold-agent gap at the surface that owns it — tool first, then catalog, then skill** — prefer the *tool* self-describing (deterministic, helps even a skill-less agent), fall back to the *catalog* (self-verifying vocabulary), reserve the *skill* for the judgment the other two can't encode. (From the T13 baseline miss: the bracketed-call-args trap → a catalog gotcha + a sharpened skill rule; the missing-per-locale-message gap → `config read` / `model describe` now expose the declared `header.locales` that drive the requirement.)
22. **The kernel is the authority on version compatibility; rulekit only classifies** — the build's versions are self-describing (`--version` / `manifest.version`); for an off-version model the kernel decides (accepts older same-major, fail-fasts on newer/different-major), and rulekit classifies that verdict into stable codes (`RK_MODEL_VERSION_SKEW` vs `…_INCOMPATIBLE`). Inform, don't second-guess the kernel; write-back never bumps the version.
23. **Refs (to fields *and* groups) are the currency across both kits; L2b codegen is dropped, not parked** — a value ref for any element (existing or just-created) used everywhere (rule scope / error-field / operands + structure-edit targets), with a thin session-bound *editor* as the *one* fluent idiom. The safety invariant: the immutable AST holds **only** pure refs, never the session-carrying editor (functional core / effects at the edge). Codegen is structurally incapable of the runtime create→reference flow (it lags the live edit); a live-node graph's one unique win (rename-tracking) fights the immutable-snapshot grain. (PROJECT-DESIGN D7; naming → §18.7.)
24. **Document-part builders fall out of the editor — no new machinery** — once the editor takes a "where to build" handle and returns refs, a `(GroupEditor, params) → structure + rules` function composes exactly like a rule fragment (finding 11). Whether a team keeps a `Money`/`Address`/`LineItems` library is their call; the claim is only that nothing extra is needed.
25. **Includes + type-defs make rulekit a multi-model tool** — rules author over mounted fields by their mount-name path exactly like local ones; the binding threads a resolver that expands the include through the kernel, and write-back keeps the include a `modelAlias` reference (**never inlined** — F6/D9). An included model's own rules travel with it unless the mount excludes them.
26. **"Does this rule actually fire?" is a first-class capability** — `evaluate`/`compute` run the model over a document instance and return fired codes / computed values; verify-**by-execution** (run a passing + a violating doc and compare fired codes) is the angle that exposes an inverted-but-kernel-valid rule, and the engine behind the eval's execution-based equivalence judge.
27. **`;;` comments are preserved via a node-identity side-channel, not new AST nodes** — the kernel drops comments from its parsed AST, so a side-channel (`Comments`, keyed by node identity) gets the common (leading-comment) case for a fraction of the blast radius of 15 new node types + their switch rewrites. Lessons: a side-channel keyed by identity is the cheap way to attach metadata to an immutable AST you don't want to re-shape, and the *author* and *preserve* halves split cleanly into separate increments.
28. **Gates over checklists** — anything an LLM can skip *will* eventually be skipped, so a criterion that matters becomes a build-failing gate derived from the live artifact, not a checklist item. (Its full realization — the CLI self-describe/diagnose conformance harness — is a CLI-tool concern in [`CLI-CONFORMANCE-SPEC`](./CLI-CONFORMANCE-SPEC.md), not this DSL/API study.)
29. **The catalog names each predicate's negation partner (`opposite`)** — the kernel has no generic `Not(…)`, so the inverse of a predicate is *another* predicate; the pairing turns the "no generic negation" trap into a one-hop lookup. A discoverability pointer, not a strict-complement claim (three-valued / formal-error semantics mean `FieldFilled`/`FieldNotFilled` aren't exhaustive). (FEATURE-GAPS G3.)
30. **A rule's legal error field is computable up front** — it must be referenced by the condition and inside its iteration scope, so `errorFieldCandidates` turns the `MVK_ERROR_FIELD_NOT_REFERENCED` reject→fix loop into an up-front pick. Two notes worth keeping: a set-based overload fed by the kernel's own `getDirectlyReferencedEntities` is robust where the rulekit converter NPEs on an inconsistent candidate, and that required a *lenient bind* (expand without the consistency gate) — a read-only capability the write path must never use. (FEATURE-GAPS G4.)
31. **Two computation laws are caught by a text-level lint before the kernel round-trip** — a precondition can't use `CustomCondition`/`RepetitionNotUnique`, and alternatives must be mutually exclusive (the kernel takes the first match in declaration order, so a duplicate precondition can never win). Matched as operator calls by EN+DE keywords; true logical disjointness needs a solver and is out of scope — the exact-duplicate case is the one that always means a bug. (FEATURE-GAPS G5.)
32. **Recurring validation idioms are a typed-DSL-backed catalogue, correct by construction** — each `patterns` idiom builds its condition through the typed DSL with violation polarity + a referenced error field baked in (the two traps otherwise re-risked each time). Built-ins are typed behind a `PatternEntry` interface a future data-template extension plugs into additively; a no-rot gate kernel-validates every example in CI. (FEATURE-GAPS G2.)
33. **A `java.time` overload removes the last format-coupled string from the typed DSL** — `dateValue(LocalDate)`/`timeValue(LocalTime)` render to the kernel's German form and can't be malformed; the `String` overload stays for the CLI/spec path where values legitimately arrive as text. (DEV-API-GAPS DG4.)
34. **Computations get the same tooling shape as rules — no sibling asymmetry** — a `ComputationDiagnostics.diagnose` peer, `Computation.Builder.build()` throwing a structured `PrecheckException` (still an `IllegalStateException`, so existing catches hold), and `ReadComputation.Opaque` carrying `canonicalText`. (DEV-API-GAPS DG2.)
35. **Explanation projections emit a self-describing `UNKNOWN`, never a cryptic `"?"`** — the computed-field kind comes from the typed `FieldRef` (which always carries a `ValueKind`) rather than a path re-lookup that could miss. (The narrow slice of DG5; the (de)serialization-boundary result records stay `String` by design.)
36. **Editing a model reads like authoring it** — the per-type field builders (`numberField`/`enumField`/…) live on the editor, and both routes assemble through a single `FieldAttrs.toField(name)`, so a field added while editing is byte-identical to one built from scratch and a metadata call in the lambda can't be silently dropped. (DEV-API-GAPS DG1.)
37. **The navigation surface reads the annotations it can write** — `FieldInfo`/`GroupInfo.annotations()`/`annotation(name)` (read back through the kernel), making "find every field carrying annotation X, then act" a plain stream filter. Fires finding 9's annotation-query trigger with the *minimum* — a per-element read, not a model-wide annotation index.
38. **Composition + presence quantifiers take a `List`, not just varargs** — so a rule assembled from a loop/stream folds cleanly (`allOf(List)`/`anyOf(List)` + list overloads of the presence quantifiers); the primitive the bulk/generated-authoring case (the §3.6 mirroring study) was missing.
39. **The most-repeated mirroring idiom ships as `a.agreesWith(b)`** — renders "both filled and equal, or both empty," so its polarity is reviewed *once* instead of per pair; with `allOf(List)` (38) a 7-field address mirror becomes a one-liner.
40. **A combinator can be written against a *root group* and applied to any subtree** — `GroupInfo` gained relative navigation (`app.str("Schedule/Name")`), the read peer of the editor's, so a rule like `scheduleConsistency(GroupInfo)` is location-independent (applies to a mounted/included sub-form). It lives on `GroupInfo` (model-aware), not `GroupRef` (a pure value — the §5c AST invariant).
41. **The write/edit not-found paths speak the same coded `Diagnostic` as validate/lint** — a reusable `PrecheckException.notFound(RkCode, path)` (`RK_NO_SUCH_RULE`/…) adopted by `ModelWriter`/`KernelAdapter`; additive (still an `IllegalStateException`). Boundary by design: `modelkit`/`core` not-found stay bare — the ⊥/layering invariants forbid them importing `Diagnostic`. (DEV-API-GAPS DG3.)
42. **The operator catalog can be browsed, not just looked up by id** — `byKeyword`/`byKind`/`byReturns`; the catalog exists to be discovered.
43. **A kernel-free `ModelResolver` SAM keeps multi-model loading off `com.mgmtp.a12.kernel.*`** — `id → DM-JSON`, bridged to the kernel resolver, so the app resolves includes/imports from its own store (a map, a service).
44. **`includeLevel` is authorable and a transitive include is distinguished on read** — `MountOptions.single().asModelRoot()` emits the group `includeLevel` (SINGLE_RG omitted = the kernel default); `includes()` is exact, `transitiveIncludes()` reads kernel-added references separately. (DEV-API-GAPS DG6.)
45. **`ModelContext.find` returns a typed `ValueKind`, not a stringly `kind`** — consistency with `FieldInfo.kind()`. (The clean slice of DG5; the wire-boundary result records intentionally stay `String`.)
46. **A custom-typed field gets its own string-shaped handle, not a loosened `str()`** — `BoundModel.custom(path)` returns a `StringRef` (kind-checking `== CUSTOM`), so a custom field's text value can be compared (`[Code] == "x"`, legal kernel grammar) through the full `StringRef` surface. The alternative — letting `str()` accept a `CUSTOM` field — was rejected to keep the *one-accessor-per-kind* invariant: each typed accessor still maps to exactly one `ValueKind`, and `str()` stays STRING-only. (DEV-API-GAPS DG13.)
47. **The builder enforces a kernel co-requirement fail-fast, with our own message** — `StringFieldBuilder.noValueValidation()` authors the value-skip flag, and `FieldTypeSpec.StringSpec` rejects the kernel-illegal pair (`noValueValidation` without line breaks, `MVK_STRING_TYPE_NO_VAL_AND_NO_LINE_BREAK`) at `build()` with a named cause — instead of letting it surface as a late kernel reject on load. Mirrors the existing pattern⟺message co-requirement check, so co-requirements caught before the kernel stay consistent. (DEV-API-GAPS DG14; the kernel fact is KERNEL-FINDINGS "STRING `noValueValidation`".)
48. **Arithmetic rendering is precedence-aware, so a precedence-overriding group is authorable without a group node** — `DslRenderer` braces a child operand that binds *looser* than its parent, so `times(plus(1, 1))` renders `[BQ] * { 1 + 1 }` (the `{…}` binds before the `*`); arithmetic whose grouping already matches natural precedence (`^` > `*`/`/` > `+`/`-`) stays brace-free and round-trips. No explicit `Dsl.group(…)` node was needed — the renderer derives the braces from the tree. (DEV-API-GAPS DG7.)
49. **Temporal arithmetic returns a date-time, and the extractors accept any datetime operand** — `addHours`/`addMinutes`/`addSeconds` return a `DateTimeExpr` (a sub-day shift *is* a date-time, matching `DateShift.Unit`'s declared kind — correcting a latent kind mismatch), and `dateFromDateTime`/`timeFromDateTime` accept any `DateTimeOperand` (a field, a `DateTime(date, time)` construction, *or* a shift), so `DateFromDateTime(AddHours(dt, 5))` composes through the typed surface. (DEV-API-GAPS DG9.)
50. **Field references are first-class operands, not only literals, in value lists and semantic indexes** — `StringRef.in(StringRef…)` / `NumberRef.in(NumberRef…)` author a value-list whose entries are `[field]` references (`FieldValueIncludedInValueList(Quantity, [BackorderQuantity])`), and `NumberRef.forIndex(FieldRef)` authors a field-keyed semantic index (`[Count For Sku]`, the lookup key being another field's value) — matching the kernel forms that previously had no typed builder. (DEV-API-GAPS DG8/DG10.)
51. **A repeatable group's row sort fields are authorable, gated on the same two preconditions as the index field** — `GroupBuilder.sortField(child, ASC/DESC)` (called repeatedly for a multi-key sort, keys applied in declaration order) emits the kernel's `sortFields` and rejects at `build()` a non-repeatable group or a non-child field, exactly like `indexField`. It is **display/USB-only**: the kernel does not reorder rows for validate/compute, so this is an authoring + read-fidelity capability, not an evaluation one (the interpreter ignores sort order — INTERPRETER-FINDINGS IF22). Verified by a kernel read-back (`getSortFields()`), since the silent-ignore deserializer hides an unhonored key. The CLI surfaces the same edit — `group modify --sort-field <child>[:asc|desc]` / `--clear-sort-fields`, `group read` echoes `sortFields`, and the `apply` group-modify op carries the same keys (shared `SortFieldArg` parser). (FEATURE-GAPS G28.)
52. **`Dsl` is a flat factory by design — for a coding agent the discovery surface is the catalog + naming, not the class shape** — an agent discovers an operator by *querying the operator catalog* (`OperatorCatalog`/`operators`) and grepping examples, not by browsing IDE autocomplete the way a human does. So the ~130 `Dsl.*` factory methods stay **flat**: one import, greppable, unambiguous (`Dsl.addYears` — no "which sub-facade?" hop), and a single surface (no flat-vs-faceted "two ways"). Sub-facades (`Dsl.dates().…`) would aid a human's autocomplete but cost an agent an indirection + a wrong-guess surface + a dual API — a *net* debt, so they're a **non-goal**. The discovery levers that serve both consumers are consistent verb-prefix **naming** and the catalog. Re-open only if `Dsl` becomes *incohesive* (mixes concerns beyond "construct a DSL node"). (DEV-API-GAPS, the `Dsl`-grouping item, resolved as out-of-scope.)

53. **The constraint read-back surface mirrors the authoring surface — typed accessors, never raw-block navigation** — `ModelDocument` reads back every constraint the per-kind builders write: `fieldPattern` / `fieldMinLength` / `fieldMaxLength` / `fieldMinValue` / `fieldMaxValue` / `fieldMaxFractionalDigits` (the peers of `enumValues`), plus the typeDefinition peers (`typeDefinitionPattern` / …) — needed because a typedef-typed field's own `fieldConfig` is *empty* (its constraints live on the typeDefinition, not the field). A consumer reads a declared constraint without knowing the schema-block quirks (number bounds are *text* under a `number` sub-block; lengths/pattern under `string`; the kernel always carries a scale, defaulting to 0 — KERNEL-FINDINGS). Surfaced by the JSON-Schema exporter, which now reads constraints *exclusively* through these accessors — the dogfood loop closing: the friction of raw-block (`findValue`) navigation drove the API, and the motivating consumer uses it (no `findValue`, no per-block `copyInt`/`copyNumber`). (DEV-API-GAPS, the read-back-accessors item, resolved.)
