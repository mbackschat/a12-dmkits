# Portable consistency checker — gaps

> **What this is** — where the kernel-free `:consistency` checker ([CONSISTENCY-API](CONSISTENCY-API.md)) reports a model differently from A12's `checkConsistency`: a class it leaves unnamed, or one it names where A12 names another. Each row cites the kernel law that measured A12's class and the checker lock that pins today's divergence. Ids are `DG<n>`, drawn from the chunks declared once in [DEV-API-GAPS](DEV-API-GAPS.md)'s `dg-id-chunks` line, which serves both ledgers.
>
> **Lifecycle.** A gap lives here only while open. When it ships, its row is DELETED in the same commit: the measured behaviour already lives in its [KERNEL-FINDINGS](KERNEL-FINDINGS.md) entry, and the checker lock turns from a divergence lock into an agreement. No shipped list, ever.
>
> **Current state.** §1 lists what is open; read it rather than this paragraph. The rows moved here from DEV-API-GAPS on 2026-09-26 with their ids unchanged, so an older citation of `DEV-API-GAPS DGn` for one of them resolves here.

## 1. Open

- **DG83 — the portable checker reports a message class A12 withholds when the condition beside it is refused for a reason the checker leaves to A12.** `FieldFilled(Reference) And Abs([Premium], [Premium]) > 0` with no message draws `MVK_ERROR_MESSAGE_MISSING,MVK_UNEXPECTED_TOKEN` in A12 and `MVK_ERROR_MESSAGE_MISSING,RULE_HAS_NO_ERRORTEXT` here, and a TAB in the text draws `INVALID_CHARACTERS` here where A12 names only the condition; `AddDays([Premium], 1)` is the operand-kind twin (kernel rows in `validate.laws.MessageParameterConditionDependencyLawsTest.whichClassesEachRefusedConditionShapeWithholds`). A12 skips the error-text checker whenever the condition errs ([KF338](KERNEL-FINDINGS.md#kf338)), and report assembly can apply that only where a family detects the defect. The report's own coverage gap on operator arity and operand kinds says so. **What would settle it:** the per-operator arity and operand-kind gates, which that gap declines as a second copy of the catalog. **Blocks nothing:** the model is refused on both sides, so only the class differs.
- **DG93 — the portable checker takes every operator argument as an entity slot.** A12's grammar types each argument slot, so a slot that takes only a literal refuses a name: `RoundUpValue(Total, NoSuchField) > 0` and `RoundUpValue(Total, Total) > 0` are both `MVK_UNEXPECTED_TOKEN` ([KF472](KERNEL-FINDINGS.md#kf472), `validate.laws.BareEntityOperandLawsTest`). The shape parser resolves the name instead, so it draws `MVK_INVALID_ENTITY` on the first and nothing on the second (divergence locks in `consistency.BareEntityOperandTest`). The report discloses the class as a coverage gap: the shape parser checks the productions' shared shape and "not each operator's own argument arity or operand kinds" (`Check.kt`). Settled by a per-operator argument grammar in the shape parser, each slot's kind measured on the kernel before it refuses. *Widened 2026-09-26 by the near-miss sweep (`adapter.laws.CheckerNearMissSweepTest`, batch S of [CONFORMANCE-PLAN](CONFORMANCE-PLAN.md)):* the same missing slot kinds leave four more shapes wrong. A bare or digit-led name in an operation slot (`RoundDown([UnitPrice], 0And)`) draws `MVK_INVALID_ENTITY` here and the token class in A12. A signed number in a literal slot (`RoundUpValue(UnitPrice, - 2)`) is silent here. A keyword constant followed by `(` (`[DeliveryDate] < Today (`) draws `MVK_EXPECTED_TOKEN_NOT_FOUND` here. And a digit sequence leading an entity slot, which A12 reads as an entity name ([KF479](KERNEL-FINDINGS.md#kf479)), is read as a number here: `MinValue(1 + Items*/Count)` is `MVK_INVALID_ENTITY` in A12 and the token class here.
- **DG94 — two checker families own the one star gate of A12's field-value read.** A starred `[ … ]` is `MVK_NO_WILDCARDS_ALLOWED` wherever the bracket stands ([KF473](KERNEL-FINDINGS.md#kf473)), and every filter-body row `FILTER_WILDCARD` was measured on is a bracketed read ([KF97](KERNEL-FINDINGS.md#kf97)). Yet `FIELD_VALUE_READ_OPERAND` leaves a star in a filter's body to `FILTER_WILDCARD`, so one gate is split between two families by position. Reports agree today, so nothing is misreported. The cost is two places to change and two spans for one gate. Settled by folding the filter arm into the bracket family. Both measurements that waited on it are in: a `$`-marked starred bracket outside a filter is `MVK_INVALID_OUTER_ITERATION`, `checkOuter` answering ahead of the bracket ([KF487](KERNEL-FINDINGS.md#kf487)); and a star outside a bracket in a body, a nested aggregate's argument, is read as a WILDCARD level with no star gate of the filter's own ([KF486](KERNEL-FINDINGS.md#kf486)). What is left is the published surface. `CheckFamily.FILTER_WILDCARD` is public API (`consistency/api/consistency.api`) and is named in every parity report under `consistency/consumer-tests/shared/parity/reports/`, so the fold removes a member from the report's family list. The bracket reader also gives a `$`-marked spec no path, so the fold has to add one for the star gate alone, while the reader's three other consumers keep setting marked reads aside. **Re-open at** the next revision of the report's family list.
- **DG102 — the portable checker leaves a constant key unjudged over a type-definition or custom index field, and over a String pattern outside the subset it matches itself.** A12 tests a constant against the index field's value validation ([KF481](KERNEL-FINDINGS.md#kf481)). The checker evaluates a declared pattern only in a subset whose matches it computes without a regex engine (`consistency.KeyPattern`), so beside `.{2}` or any pattern with an escape, a group or alternation a key meeting its length bounds is unjudged and every gate behind it stands down: the two declared rows of `adapter.laws.CheckerIndexKeyConstantAgreementTest`. A type-definition or a custom index field is unjudged and unmeasured. **What would settle it:** kernel rows for a type-definition and a custom index field; a wider pattern subset, each construct added with its boundary measured on the kernel and its Java match executed. **Blocks nothing:** an under-report.
- **DG113 — the portable checker's element-name family does not follow A12's path alphabet on three rows.** A group named `Parté` and a field named `Codeé` are `MVK_PATH_INVALID` in A12, whose group alphabet takes the German umlauts and `ß` and no other non-ASCII letter ([KF315](KERNEL-FINDINGS.md#kf315), corrected), and the checker reports nothing on either. A field named `Co.1de` is `MVK_PATH_INVALID` alone, since a piece after a dot must begin with a letter, and the checker names `MVK_NAME_INVALID_DOT_COLON_A12_DV` instead (kernel rows in `validate.laws.FieldTypeMessageTextLawsTest.anInvalidPathStopsTheCheck`). `FieldTypeMessageText.reachedByTheElementWalk` already states that alphabet for the withholding it needs. **What would settle it:** `ELEMENT_NAME_ALPHABET` reporting `MVK_PATH_INVALID` from that one predicate, with a kernel row for a non-umlaut, non-ASCII group letter beside `é` and for the `.`-then-digit field against its `.`-then-letter twin. **Blocks nothing:** the first is an under-report, and on the second the model is refused on both sides, so only the class differs.
- **DG114 — the portable checker judges a field an `ONLY` variant filter deletes.** A12 removes such a field before its element walk, so a tab in its pattern message is ADMITTED ([KF490](KERNEL-FINDINGS.md#kf490), `validate.laws.FieldTypeMessageTextLawsTest`), and `FIELD_TYPE_MESSAGE_TEXT` reports `INVALID_CHARACTERS` there: an over-rejection. Twenty field families walk `declarations()` rather than the default-variant population, so the class is wider than one family, and which of them A12's other field gates also skip is unmeasured. Settled by the field arm of [CONFORMANCE-PLAN](CONFORMANCE-PLAN.md)'s sweep, which puts an `ONLY` filter on every field that carries a defect; it blocks nothing but the M3 exit.
- **DG117 — the portable checker does not type an arithmetic side of a comparison.** A12 types `[Premium] + 1` as a Number, so a computation copying it into a String draws `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING` ([KF483](KERNEL-FINDINGS.md#kf483)), while the checker's comparison families read a side only when it is one entity spec or a written-out constant and stay silent (`adapter.laws.CheckerFieldCopyCrossAgreementTest`, `CheckerComputationJoinedConditionAgreementTest`). Measured on the text arm of the computation carrier only. Settling it needs the result type A12 gives each arithmetic shape, a Date operand and a scale included, measured on every arm and on the rule carrier before the side reader types one.
