# Portable consistency checker — gaps

> **What this is** — where the kernel-free `:consistency` checker ([CONSISTENCY-API](CONSISTENCY-API.md)) reports a model differently from A12's `checkConsistency`: a class it leaves unnamed, or one it names where A12 names another. Each row gives the input, A12's measured class, the kernel law that measured it, and the plan item that settles it. Ids are `DG<n>`, drawn from the chunks declared once in [DEV-API-GAPS](DEV-API-GAPS.md)'s `dg-id-chunks` line, which serves both ledgers.
>
> **Lifecycle.** A gap lives here only while open. When it ships, its row is DELETED in the same commit: the measured behaviour already lives in its [KERNEL-FINDINGS](KERNEL-FINDINGS.md) entry, and the sweep ledger turns the divergence into an agreement. No shipped list, ever.
>
> **Current state.** Since 2026-09-26 the checker's divergences are discovered by the near-miss sweep, and its committed ledger (`adapter/src/test/resources/checker-near-miss/clusters.tsv`) is their list. The rows below were found by hand before that, so their inputs are kept here until they become sweep seeds. Each row names the missing structure behind it and the stage rebuild in [CONFORMANCE-PLAN](CONFORMANCE-PLAN.md) that settles it; none is patched in the family it names.

## 1. Open

- **DG83 — a message class beside a refused condition.** `FieldFilled(Reference) And Abs([Premium], [Premium]) > 0` with no message is `MVK_ERROR_MESSAGE_MISSING,MVK_UNEXPECTED_TOKEN` in A12; the checker adds or substitutes a message class, and a tab in the text draws `INVALID_CHARACTERS` where A12 names only the condition. `AddDays([Premium], 1)` is the operand-kind twin (`validate.laws.MessageParameterConditionDependencyLawsTest`, [KF338](KERNEL-FINDINGS.md#kf338)). A refused condition turns the message's parameter check into `INVALID_CONDITION` ([CHECKER-RECONSTRUCTION-PROPOSAL](CHECKER-RECONSTRUCTION-PROPOSAL.md) §1). Settled by R3 and R5.
- **DG93 — a digit sequence in an entity slot.** `FieldFilled(5)`, `AbsValue(5)` and `MinValue(1 + Items*/Count)` are `MVK_INVALID_ENTITY` in A12, since a digit sequence is a name ([KF479](KERNEL-FINDINGS.md#kf479), [KF492](KERNEL-FINDINGS.md#kf492)); the checker is silent on the first two and says `MVK_UNEXPECTED_TOKEN` on the third (`adapter.laws.CheckerArgumentSlotAgreementTest`). Settled by R3.
- **DG94 — two checker families own one star gate.** `FIELD_VALUE_READ_OPERAND` and `FILTER_WILDCARD` split A12's one field-value star gate ([KF473](KERNEL-FINDINGS.md#kf473), [KF97](KERNEL-FINDINGS.md#kf97)) by position. Reports agree, so this is a structure defect, not a divergence. Dissolved when R3 deletes both families; `CheckFamily.FILTER_WILDCARD` is public API and named in the parity reports, so that landing revises the report's family list.
- **DG102 — a constant key the checker cannot judge.** A12 tests a constant key against the index field's value validation ([KF481](KERNEL-FINDINGS.md#kf481)). The checker matches only a regex-free pattern subset (`consistency.KeyPattern`), so beside `.{2}`, an escape, a group or an alternation the key is unjudged (`adapter.laws.CheckerIndexKeyConstantAgreementTest`). A type-definition or custom index field is unjudged and unmeasured. Settled by a Java-compatible pattern judge on JVM and JS and by P3's typedef and custom-index hosts; independent of the rebuild.
- **DG113 — element names against A12's path alphabet.** A group `Parté` and a field `Codeé` are `MVK_PATH_INVALID` in A12, whose group alphabet takes the German umlauts and `ß` and no other non-ASCII letter ([KF315](KERNEL-FINDINGS.md#kf315)); the checker is silent. A field `Co.1de` is `MVK_PATH_INVALID` alone, and the checker names `MVK_NAME_INVALID_DOT_COLON_A12_DV` (`validate.laws.FieldTypeMessageTextLawsTest.anInvalidPathStopsTheCheck`). Settled by R4 with P3's name edits.
- **DG114 — a field an `ONLY` variant filter deletes.** A12 checks the default-variant element container, so a tab in such a field's pattern message is admitted ([KF490](KERNEL-FINDINGS.md#kf490)), and the checker reports `INVALID_CHARACTERS`: an over-rejection, on a family that walks declarations rather than the default variant. Settled by R4, with P3's variant filters measuring which other field gates it reaches.
- **DG117 — an arithmetic side of a comparison.** A12 types `[Premium] + 1` as a Number, so copying it into a String is `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING` ([KF483](KERNEL-FINDINGS.md#kf483)); the checker types only a lone entity spec or constant and is silent (`adapter.laws.CheckerFieldCopyCrossAgreementTest`, `CheckerComputationJoinedConditionAgreementTest`). A12's check actions type every operation bottom-up. Settled by R3.
- **DG118 — `Min` and `Max`'s component-set gate.** A `yyyy-MM` read beside a `yyyy-MM-dd` one inside `Min(...)` is `MVK_DATEFORMATS_NOT_COMPATIBLE` in A12 ([KF96](KERNEL-FINDINGS.md#kf96)); the checker judges only the entity-list carriers (`consistency.TemporalAggregateOperandsTest`). Same missing structure as DG117; settled by R3.

## 2. Out of scope

- **What a document's evaluation fires.** The checker judges a model statically; runtime behaviour is the interpreter's, and its divergences are [INTERPRETER-GAPS](INTERPRETER-GAPS.md)'.
