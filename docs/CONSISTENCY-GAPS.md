# Portable consistency checker — gaps

> **What this is** — where the kernel-free `:consistency` checker ([CONSISTENCY-API](CONSISTENCY-API.md)) reports a model differently from A12's `checkConsistency`: a class it leaves unnamed, or one it names where A12 names another. Each row cites the kernel law that measured A12's class and the checker lock that pins today's divergence. Ids are `DG<n>`, drawn from the chunks declared once in [DEV-API-GAPS](DEV-API-GAPS.md)'s `dg-id-chunks` line, which serves both ledgers.
>
> **Lifecycle.** A gap lives here only while open. When it ships, its row is DELETED in the same commit: the measured behaviour already lives in its [KERNEL-FINDINGS](KERNEL-FINDINGS.md) entry, and the checker lock turns from a divergence lock into an agreement. No shipped list, ever.
>
> **Current state.** §1 lists what is open; read it rather than this paragraph. The rows moved here from DEV-API-GAPS on 2026-09-26 with their ids unchanged, so an older citation of `DEV-API-GAPS DGn` for one of them resolves here.

## 1. Open

- **DG83 — the portable checker reports a message class A12 withholds when the condition beside it is refused for a reason the checker leaves to A12.** `FieldFilled(Reference) And Abs([Premium], [Premium]) > 0` with no message draws `MVK_ERROR_MESSAGE_MISSING,MVK_UNEXPECTED_TOKEN` in A12 and `MVK_ERROR_MESSAGE_MISSING,RULE_HAS_NO_ERRORTEXT` here, and a TAB in the text draws `INVALID_CHARACTERS` here where A12 names only the condition; `AddDays([Premium], 1)` is the operand-kind twin (kernel rows in `validate.laws.MessageParameterConditionDependencyLawsTest.whichClassesEachRefusedConditionShapeWithholds`). A12 skips the error-text checker whenever the condition errs ([KF338](KERNEL-FINDINGS.md#kf338)), and report assembly can apply that only where a family detects the defect. The report's own coverage gap on operator arity and operand kinds says so. **What would settle it:** the per-operator arity and operand-kind gates, which that gap declines as a second copy of the catalog. **Blocks nothing:** the model is refused on both sides, so only the class differs.
- **DG90 — the portable checker is silent on an aggregate inside a `Having` body.** A12 refuses a nested FILTER by the construct gate, `Sum(Claims*/Paid Having Sum(Claims*/Units Having [Claims/Units] > 5) > 0) > 0` being `MVK_DISALLOWED_CONSTRUCT_IN_FILTER_CONDITION`; an unstarred nested operand by its own chain before that, `MVK_NO_WILDCARD`; and an aggregate with no filter of its own by the iteration gate, `Sum(Claims*/Paid Having Sum(Claims*/Units) > 0) > 0` being `MVK_NO_ITERATION_FOR_WILDCARD` ([KF467](KERNEL-FINDINGS.md#kf467), `validate.laws.FilterBodyComparisonLawsTest`, divergence locks in `consistency.FilterBodyComparisonTest`). The checker draws none of the three; a comparison in such a body is still typed and named. **What would settle it:** the nested operand's chain ordered against the outer body's scope and index gates, measured, so the walk can take a nested aggregate without guessing which answers first. **Blocks nothing:** an under-report.
- **DG93 — the portable checker takes every operator argument as an entity slot.** A12's grammar types each argument slot, so a slot that takes only a literal refuses a name: `RoundUpValue(Total, NoSuchField) > 0` and `RoundUpValue(Total, Total) > 0` are both `MVK_UNEXPECTED_TOKEN` ([KF472](KERNEL-FINDINGS.md#kf472), `validate.laws.BareEntityOperandLawsTest`). The shape parser resolves the name instead, so it draws `MVK_INVALID_ENTITY` on the first and nothing on the second (divergence locks in `consistency.BareEntityOperandTest`). The report discloses the class as a coverage gap: the shape parser checks the productions' shared shape and "not each operator's own argument arity or operand kinds" (`Check.kt`). Settled by a per-operator argument grammar in the shape parser, each slot's kind measured on the kernel before it refuses.
- **DG94 — two checker families own the one star gate of A12's field-value read.** A starred `[ … ]` is `MVK_NO_WILDCARDS_ALLOWED` wherever the bracket stands ([KF473](KERNEL-FINDINGS.md#kf473)), and every filter-body row `FILTER_WILDCARD` was measured on is a bracketed read ([KF97](KERNEL-FINDINGS.md#kf97)). Yet `FIELD_VALUE_READ_OPERAND` leaves a star in a filter's body to `FILTER_WILDCARD`, so one gate is split between two families by position. Reports agree today, so nothing is misreported. The cost is two places to change and two spans for one gate. Settled by folding the filter arm into the bracket family, after measuring the `$`-marked bracket read outside a filter, which that family does not judge yet, and a star outside a bracket in a filter's body, such as a nested aggregate's argument (DG90's shapes). Belongs with DG88 and DG90.
- **DG102 — the portable checker leaves a constant key unjudged over a String index with a declared pattern.** A12 matches the constant with Java's `String.matches`, so with `K` a String patterned `[A-Z]{2}[0-9]`, `Sum(Refs/Amount For "ab1") > 0` is `MVK_INDEX_VALUE_INVALID` and `For "AB1"` names the arity class ([KF481](KERNEL-FINDINGS.md#kf481)). The checker also runs on a JavaScript target, where a Java pattern does not evaluate identically, so it leaves the key unjudged and every gate behind it stands down: the two declared rows of `adapter.laws.CheckerIndexKeyConstantAgreementTest`. A type-definition or a custom index field is unjudged too, and unmeasured. **What would settle it:** a pattern subset both targets evaluate alike, its boundary measured on the kernel. **Blocks nothing:** an under-report.
- **DG88 — the portable checker is silent on a `$`-marked filter reference that no iteration encloses.** A12 walks it as the rule's own read: from a fixed group, `Sum(Returns*/Weight Having [$Invoices/Weight] == [Returns/Weight]) > 0` is `MVK_ERROR_FIELD_NO_INDEX` with `Invoices` keyed and the marked read of the unkeyed `Returns` is `MVK_NO_WILDCARD` ([KF353](KERNEL-FINDINGS.md#kf353), `validate.laws.IndexFieldBaseTypeLawsTest`, divergence locks in `consistency.IndexFieldBaseTypeTest`). The checker sets every body carrying the marker aside, in both the operand-scope walk and the filter-body gate. **What would settle it:** the marked read under an enclosing iteration and inside a nested filter, measured, so the walk can take the marked references of a body without guessing what the marker binds. **Blocks nothing:** an under-report, never a wrong class.
- **DG81 — the portable checker is silent on `FirstFilledValue` over a group whose fields differ in type.** `FirstFilledValue(Insured) > 0`, over a group holding a string and a number, is `MVK_VARYING_TYPES_NOT_ALLOWED` in A12 (row locked in `validate.laws.GroupOperandRepetitionScopeLawsTest.theNonRepeatingTwinsPassTheWalk`), and the checker's type gate reads only listed fields, not a group's expansion, so it reports nothing. Settled by a checker row beside that lock; blocks nothing but the silence.
- **DG80 — the portable checker is silent on a starred `RepetitionNotUnique` key that resolves.** `RepetitionNotUnique(Claims*/ClaimRef)` is `MVK_NO_WILDCARDS_ALLOWED` in A12, from the key list's own gate, and the checker carries no such gate, so it reports nothing ([KF355](KERNEL-FINDINGS.md#kf355); row locked in `validate.laws.GroupOperandAndKeyResolverClassLawsTest`, silence in `consistency.GroupOperandAndKeyResolverClassTest`). A starred key that does NOT resolve is already exact, since the reference walk answers first ([KF356](KERNEL-FINDINGS.md#kf356)). **What would settle it:** the key list's gates in [KF355](KERNEL-FINDINGS.md#kf355)'s order, category and group before the wildcard, reported only where the key resolves. **Blocks nothing:** an under-report, never a wrong class.
