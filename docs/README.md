## The interpreter

- **[INTERPRETER-SPEC.md](INTERPRETER-SPEC.md)** — the interpreter's **design decision + contract** (BUILT): an isolated, native-safe runtime evaluator that interprets the rule AST instead of generating/evaluating host code. The shared implementation is proven on JVM/GraalVM-native and Node; browser packaging/verification remains a tracked gap. It owns the non-functional contract too: **low first-answer latency**, **high warm performance**, and **low relative footprint** (bounded performance caches explicitly allowed/advised); its exact numerical values are candidate calibration budgets pending scenario definition, compliant measurement, and owner ratification.
- **[INTERPRETER-ARCHITECTURE.md](INTERPRETER-ARCHITECTURE.md)** — the interpreter's **implementation architecture** (the *how*): Kotlin Multiplatform + the dual JVM/JS targets (the one `expect/actual` decimal shim), the `model ← ast ← parse`, `…← eval` package layering, parsing/AST/data structures, the **generator-ready runtime-semantics layering** (Kleene 3VL, the operator registries), the indexed/cache-heavy performance design and its owner-scoped relative-footprint discipline, the **kernel-as-oracle** correctness approach (the differential + the A–E harness series + clean-room), and special topics.
- **[INTERPRETER-FINDINGS.md](INTERPRETER-FINDINGS.md)** — the interpreter's numbered **design-findings** record (its peer of `API-FINDINGS.md`): the *why* behind how the evaluator mirrors the kernel (the clean-room **+ exact-match** #1 rules, enum-keyed operator dispatch, value-list via the typed `==` path, the `$field$`/formal-error own-text divergences, the `GroupFilled` context seam, the injected clock, ISO-text TIME). A rationale record; the routing rule — kernel-behavior truths to `KERNEL-FINDINGS.md`, interpreter design/treatment here.
- **[INTERPRETER-PERFORMANCE.md](INTERPRETER-PERFORMANCE.md)** — the interpreter's single living **non-functional measurement** doc: certification protocols for first-answer p95, warm throughput/scaling, fair kernel-Java comparison, and relative dependency/artifact/runtime footprint; benchmark on **real documents**, never the `RepDoc` shortcut. It also holds the kernel-optimization study, optimization catalog, verification status, provisional footprint baseline, and dated performance results.
- **[INTERPRETER-GAPS.md](INTERPRETER-GAPS.md)** — the interpreter's **open-issues tracker** (the `-GAPS` family, peer of `DEV-API-GAPS`): the single tracking surface for open `:interpreter` gaps, deferred items, and to-fix issues. §1 owns active work, §2 deferred/trigger-gated work, and §3 verified non-goals; shipped rows are deleted after their rationale graduates to an `IF<n>` finding. The index deliberately does not repeat volatile live IG ranges or statuses.
- **[IG-IMPLEMENTATION-REVIEW.md](IG-IMPLEMENTATION-REVIEW.md)** — the self-contained **implementation-review ledger** for IG/IF landings: reviewed commits, exact evidence, required corrections, acceptance checks, completion records, and resolution notes. Reviewers independently verify new chapters; implementors use completed chapters as authoritative work briefs and re-check only the live locations needed for the recorded fixes.
- **[INTERPRETER-DROPIN-CERTIFICATE.md](INTERPRETER-DROPIN-CERTIFICATE.md)** — the historical **eval-surface compatibility certificate** used to retire `--kernel` eval (“Scope A” = evaluation only), with each capability tied to its named evidence. The retirement remains executed and the kernel remains the differential oracle. IF140 completed the derived capability × strategy × coverage-tier matrix; the remaining legal-input/platform/preparation/API gaps keep the certificate at strong evidence on the exercised surface rather than a current strict whole-domain verdict. [INTERPRETER-GAPS.md](INTERPRETER-GAPS.md) is the exhaustive live status. Recorded by [INTERPRETER-FINDINGS.md](INTERPRETER-FINDINGS.md) IF122 and corrected by IF134/IF135/IF140.
- **[OPERATOR-API-PROPOSAL.md](OPERATOR-API-PROPOSAL.md)** — proposal for a zero-setup, TypeScript-first API over the complete direct A12 value-semantic boundary, with every example variable explicitly typed and every public/support type defined and explained: immutable value types, exact native wrapping/checked unwrapping, discoverable scalar namespaces, homogeneous native arrays with indexed conversion, collection reductions/predicates, and immediate combinators. Kotlin Multiplatform owns every semantic operation once; the JVM projection is secondary, while JSON documents, field state, repetitions, sessions, and symbolic evaluation stay outside this API.
- **[INTERPRETER-API-PROPOSAL.md](INTERPRETER-API-PROPOSAL.md)** — optional working proposal for the higher model-bound Kotlin Multiplatform API, TypeScript-first with a secondary Java façade: explicitly typed and explained variables/types, prepared definitions, traversable model metadata, lossless placement input, exact field-aware `DocumentCellValue` insertion/removal, typed instantiated-row enumeration, and one-pass correlated storage/storage-value/evaluation/formal-support inspection. It also covers per-interpreter customization factories, model registrations, optional registered configurations, multiple active interpreter instances, bounded multi-threaded service pooling with reentrancy-safe lifecycle, validation, computations, and optional prepared programs. The normal service call needs only a registered model, placement document, and options; custom configuration registration exists solely to isolate custom types/conditions/charsets. It requires warm `D1, D2, D1, D2` reuse and concurrent same-model scaling without mandating one shared reentrant evaluator.
- **[ZOD-INTEGRATION-PROPOSAL.md](ZOD-INTEGRATION-PROPOSAL.md)** — optional proposal for **Zod adapters** over the TypeScript projections of the Operator API and Interpreter API: two opt-in packages (`@a12/operators-zod` for exact native/wire-to-A12 scalar codecs + Zod composition; `@a12/interpreter-zod` for strict portable DTO schemas, an optional model-owner-bound snapshot adapter, and lossless validation-report projections). Zod stays outside Kotlin `commonMain`, the base `@a12/operators`/`@a12/interpreter` JS artifacts, the evaluator, and the Java APIs — an app that never installs the adapters pays no Zod dependency, bundle, startup, or runtime cost.
- **[SEED-GENERATOR-FUZZ-SPEC.md](SEED-GENERATOR-FUZZ-SPEC.md)** — the **model-driven seed generator** (`SeedGenerator` — best-effort model-derived candidate documents from a model, kernel-free + multiplatform, via the `PlacementSink` seam) and the **differential fuzz net** built on it (`InterpreterKernelFuzzTest` — random documents, assert interpreter == kernel, the exactness multiplier): the data flow, the value/rows strategies, the diverse fuzz model, the bug track record, and the per-operator extension loop. The generator's consumers (perf harness, the `dmtool model seed` verb) live in their own docs.
