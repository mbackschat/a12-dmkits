# a12-dmkits docs — index

What each document under `docs/` holds, so you can jump to the right one. This is an *index*, not policy: the project's working conventions (language, fixture sourcing, coding style, documentation discipline, testing strategy, build) live in [`../CLAUDE.md`](../CLAUDE.md).

## Design & vision

- **[PROJECT-DESIGN.md](PROJECT-DESIGN.md)** — the one argument: vision (the bidirectional *read → explain → modify → diff → validate* loop), requirements (`Fn`/`Nn`/`Dn`), architecture, the operator-catalog spine, the decision log (§17), the phased roadmap (§16 — phasing *intent*; what's built is shown by the docs + demos), and the **modelkit addendum (§21)** — the structure-authoring peer of rulekit (fork #8): why it's worth it, why not `betterbuilders`, the formalize-the-knowhow gradient + five options, a material-source evaluation, and the read→edit→write-back plan. Densely cross-referenced by stable anchors; component *detail* splits out into specs rather than fragmenting the argument.
- **[ARCHITECTURE.md](ARCHITECTURE.md)** — the *structural* view of the system **as it is today**: the big-picture component map, the Gradle units (library `:` / opt-in `:adapter` / `:cli`) and their dependencies, the library's package layering (`dm.core` + the sibling kits `dm.rulekit` ⊥ `dm.modelkit` + `dm.edit`), the N8/D15 kernel-coupling boundary, the public API + data-only out-surface, and the **CLI** (picocli, the self-describing surface, native-image complications, how the eval/probe harnesses exercise it). Describes the present only — no roadmap/status (§7 explains why and how it stays living). Complements the design's conceptual component view (§15).
- **[INTERPRETER-SPEC.md](INTERPRETER-SPEC.md)** — the interpreter's **design decision + contract** (BUILT): an isolated, **native-safe + browser-capable runtime evaluator** that **interprets** the rule AST instead of generating-and-eval'ing code on the fly — removing the GraalVM Groovy ceiling that bars the runtime-eval verbs. The decision (interpret, not codegen) + honest tradeoffs, Kotlin-Multiplatform rationale, the owned-vs-delegated boundary, standalone-as-dependency-hygiene, verification against the differential oracle, and (§8) the in-repo placement kept clean by a purity lint. Both acceptance criteria are met (native runtime verbs + standalone full/partial validation); §10 records how it was built (spike → in-repo build-out).
- **[INTERPRETER-ARCHITECTURE.md](INTERPRETER-ARCHITECTURE.md)** — the interpreter's **implementation architecture** (the *how*): Kotlin Multiplatform + the dual JVM/JS targets (the one `expect/actual` decimal shim), the `model ← ast ← parse`, `…← eval` package layering, parsing/AST/data-structures, the **generator-ready runtime-semantics layering** (Kleene 3VL, the operator registries), the **performance techniques** (indexed placements, common-prefix cross-level resolution, star aggregation, nested/parallel iteration), the **kernel-as-oracle** correctness approach (the differential + the A–E harness series + clean-room), and special topics (the Groovy ceiling lifted, formal-error 3VL suppression, polarity, partial validation, custom conditions, the seed generator).
- **[INTERPRETER-FINDINGS.md](INTERPRETER-FINDINGS.md)** — the interpreter's numbered **design-findings** record (its peer of `API-FINDINGS.md`): the *why* behind how the evaluator mirrors the kernel (the clean-room **+ exact-match** #1 rules, enum-keyed operator dispatch, value-list via the typed `==` path, the `$field$`/formal-error own-text divergences, the `GroupFilled` context seam, the injected clock, ISO-text TIME). A rationale record; the routing rule — kernel-behavior truths to `KERNEL-FINDINGS.md`, interpreter design/treatment here.
- **[INTERPRETER-PERFORMANCE.md](INTERPRETER-PERFORMANCE.md)** — the interpreter **performance** doc (the single living one): the method (benchmark on **real documents**, never the `RepDoc` shortcut; **measured against the kernel**), the **kernel-optimization study from source + the biases to re-check**, the optimization catalog, and the dated results log. (The earlier eval-strategy *design proposal* was superseded by measurement and archived — `archived/INTERPRETER-PERFORMANCE-DESIGN.md`.)
- **[INTERPRETER-GAPS.md](INTERPRETER-GAPS.md)** — the interpreter's **open-issues tracker** (the `-GAPS` family, peer of `DEV-API-GAPS`): the single tracking surface for open `:interpreter` gaps, deferred items, and to-fix issues (the live `IG<n>` items + §3 out-of-scope; shipped/retired ones are deleted), so `INTERPRETER-FINDINGS.md` stays settled knowhow (no dispositions). §1 open (currently none), §2 deferred (with re-open triggers), §3 out-of-scope. When a gap ships it graduates to a numbered `IF<n>` finding and its row is **deleted** from the ledger (git + the finding are the record — no "shipped" list); e.g. the `../`-relative parse gap shipped as IF25.
- **[SEED-GENERATOR-FUZZ-SPEC.md](SEED-GENERATOR-FUZZ-SPEC.md)** — the **model-driven seed generator** (`SeedGenerator` — valid-by-construction documents from a model, kernel-free + multiplatform, via the `PlacementSink` seam) and the **differential fuzz net** built on it (`InterpreterKernelFuzzTest` — random documents, assert interpreter == kernel, the exactness multiplier): the data flow, the value/rows strategies, the diverse fuzz model, the bug track record, and the per-operator extension loop. The generator's consumers (perf harness, future `dmtool seed` verb) live in their own docs.
- **[SEMANTICS-FORMALIZATION-PROPOSAL.md](SEMANTICS-FORMALIZATION-PROPOSAL.md)** — the **proposal** (unbuilt) for formalizing the kernel semantics beyond today's surfaces: the portable **conformance corpus** (capture once from the real kernel → replay against interpreter JVM/JS, both kernel codegen strategies, and future third-party engines), the kernel-free **property pack** (∀-laws in `commonTest`, runs on JS), the catalog **semantic facets** with their four machine consumers (enricher, lints, judge, generated corpus cases), and the consolidation moves (semantics navigation map, re-homing sweep, the `-GAPS` rename). Work items carry per-item **model assignments** (BEST_MODEL for contracts/triage, REGULAR_MODEL for guard-net-insured execution; switch only at work-item boundaries). Graduates into TESTING-SPEC / a corpus spec / CATALOG-SPEC as items ship.
- **[SCHEMAKIT-SPEC.md](SCHEMAKIT-SPEC.md)** — the **`:schemakit` contract** (the JSON-Schema transcoder, graduated from the proposal; rationale lives in the [archived proposal](archived/JSON-SCHEMA-PROPOSAL.md)). The headline is **§1 the dependency boundary**: schemakit reaches the kernel **only through the project's own mediated modules** (root `:` facade, `:adapter`'s N8 type-converting boundary — permitted, 2026-06-28, and `:interpreter`), never the raw kernel jars directly; its own source imports no kernel type (`verifySchemakitPurity`). Plus a **reuse-first** owner directive (don't rebuild existing capability — surface gaps and let the owner decide). Plus the module/package shape (JVM/Java, native-safe, package `…dm.schemakit`), the **§4d at-a-glance import/export coverage tables**, the **§4f synthesized-rule fire-condition table**, **§4g dialect support (JSON Schema + OpenAPI 3.0/3.1/3.2)**, the `dmtool model import-jsonschema`/`export-jsonschema` verbs, the project-or-carry mapping contract, the round-trip + kernel-accept verification gates, and the increment plan. **Library built** (import maps or surfaces every feature; export best-effort) — see git for history.
- **[SCHEMAKIT-GAPS.md](SCHEMAKIT-GAPS.md)** — the **`:schemakit` import-gaps tracker** (the `-GAPS` family, peer of `DEV-API-GAPS`): the importer's open build queue + the decisions that bound its reach. A shipped gap is **deleted** (SCHEMAKIT-SPEC §4 is the record), so the sections are dispositions, not history: **§1 open** (currently **none** — the synthesis backlog is drained), **§2** the recorded `if/then/else` pragmatic-vs-strict semantic decision, **§3 declined / deferred** (feasible but deliberately not built — nested/compound `not` and `contains` descending into a nested array / arbitrary combinator on ROI; live Tier-2 and the `ExternalSchemaProfile` seam on architecture cost — each with a re-open trigger), **§4 not feasible** (`not {type}`, cross-kind unions, `$dynamicRef`, `unevaluated*`, `minItems`, true cyclic includes — no a12 form at all).
- **[CLI-SPEC.md](CLI-SPEC.md)** — the **`dmtool` CLI tool spec**: the target-first verb surface (`dmtool -m <model> <target> <op>`), the uniform result envelope, the **op taxonomy** (Local / Cascading / Refactor) and the **refactor safety gate** (§6 — check-before-mutate, the earns-a-verb bar, per-refactor preconditions), the self-describing surface (manifest/schema/operators/diagnostics), `apply`/`batch`, and packaging/sizing (§10–11).
- **[CLI-CONFORMANCE-SPEC.md](CLI-CONFORMANCE-SPEC.md)** — the **self-explain + diagnosis harness**: the diagnostic contract (every domain error is a structured, coded, fixable envelope), the self-explain criteria, the anti-pattern catalog, the **gates** that enforce each (the conformance fuzzer, registry parity, single-source derivation), the never-stale guarantee, and the verb-authoring checklist.
- **[MODEL-REVIEW-SPEC.md](MODEL-REVIEW-SPEC.md)** — the **contract + rationale** for the human **review & inspection** surface over LLM-driven model edits: the **two verbs sharing one engine** (`model report` to comprehend, `model diff` to review) + `model normalize`, the **Phase-0 deterministic order-preserving writer** (the idempotent-round-trip invariant), the diff **change model + change kinds**, the loosening>tightening **risk taxonomy**, layered **polarity detection** + AST-level change classification, the **Hybrid gloss** + the gloss-vs-message drift signal, the *structural vs. behavioral* diff levels (§5e), and the **rendering & narrow-mermaid policy** matched to dmtool's tree+text shape. **§9 carries the rationale** — the problem (baseline/altitude/**trust**), the reviewer's six jobs, and the settled forks. - **[EVAL-SPEC.md](EVAL-SPEC.md)** — the self-sufficiency eval & benchmark (N6/N1): the method (a **clean subagent** as the LLM-under-test, since self-eval is invalid), the material boundary, objective+soft-regression scoring, the build-measure-learn loop, the probe protocol, and the runner cost model + execution architecture (§8). The *method* — not the task inventory (`eval/TASKS.md`) or the numbers (`eval/RESULTS.md`).
- **[../eval/TASKS.md](../eval/TASKS.md)** — the per-task **catalog** (sibling of the runner, outside `docs/`): every eval task's intent + what it exercises (the rulekit operator-coverage map + the modelkit/mixed families). The *inventory*; the schema/gold-shapes live in `eval/README.md`.
- **[../eval/RESULTS.md](../eval/RESULTS.md)** — the dated **results log** (sibling of the runner, outside `docs/`): baselines, per-change lifts, model comparisons, and pass@k runs, newest first. EVAL-SPEC is the fixed method; this is the moving record.
- **[PROBE-SPEC.md](PROBE-SPEC.md)** — the **probe** harness: the *other* experience instrument, focused not on CLI self-sufficiency but on **shipped-product DX** (the **native** binary + the skill, over a realistic **multi-prompt** session). The method — why the eval can't see native/delivery/multi-step defects, the objective logging-shim capture, gold-from-existing-models as the correctness anchor, the six analysis dimensions, and the discover→fix→graduate-into-a-guard loop. **No k, no score** — one deep session per task, a diagnostic report. How-to + layout: [`../probe/README.md`](../probe/README.md); scenarios: `../probe/tasks/`; findings: `../probe/reports/`.
