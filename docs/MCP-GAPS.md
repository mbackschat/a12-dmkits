# dmtool over MCP — gaps

> **What this is.** Open and deferred gaps on the **MCP server surface** that [`MCP-SPEC.md`](MCP-SPEC.md) owns — the wire, the tool projection, and the content rules of `dmtool mcp`. Rows carry `MG<n>` ids. The verb surface itself stays with [`CLI-SPEC.md`](CLI-SPEC.md) and the agent-facing conformance axis with [`CLI-CONFORMANCE-GAPS.md`](CLI-CONFORMANCE-GAPS.md); a gap that is really about a *verb* belongs there, not here.
>
> **Lifecycle.** A gap lives here only while open. When it ships its row is DELETED in the same commit and its rationale graduates to [`MCP-SPEC.md`](MCP-SPEC.md); git is the what/when. No shipped list, ever.
>
> **Current state.** The deferrals below were all decided while the design was being built, not discovered afterwards, and each names what would re-open it. The design record they were taken against is the archived [MCP-SUPPORT-PROPOSAL](archived/MCP-SUPPORT-PROPOSAL.md).

---

## 1. Open

- **MG10 — `tools/list` is 349 KB, and 86 % of it is the same schema 23 times.** Measured 2026-08-06 against the packaged launcher: the frame is **348,768 bytes** (~87k tokens at 4 bytes/token), of which `outputSchema` is **302,358 bytes** — the served `result` schema, **13,146 bytes**, repeated for each of the 23 eligible tools. `inputSchema` is 37 KB and every description together is 4.7 KB, so nothing else is close.

  The repetition is a direct consequence of two decisions that are each right on their own: `outputSchema` is per-`Tool` in MCP, and it must be the **served** document with its referents bundled, because a `$ref` to a sibling is one the client cannot resolve (and the specification forbids auto-dereferencing a network `$ref`). A host that injects tool definitions into a model's context pays that once per call.

  **This is a real cost, not a deferral, and the fix needs a decision rather than a default.** The candidates, none free: drop `outputSchema` and lose the conformance guarantee on 23 tools; publish a *compact* projection of the result schema (accurate but no longer the same document the CLI serves, which is the property §6 of the spec leans on); or rely on the host's progressive-discovery path, which the client guidance describes but which is a non-normative example range and unmeasured here. **Settle it before a host with a tight definition budget is the one that discovers it.**

- **MG11 — every tool offers `model`, including the ones that ignore it.** `-m/--model` is inherited by every leaf, so the registry's "does this op take a subject model?" test is true even for `dm.catalog` (the four self-describing verbs) and `dm.model.generate` (`model new` makes one). The property is *accepted* by picocli rather than false, but it invites a caller to attach an 11 KB model to a catalogue lookup, and the tool description says so in words. The honest fix is a published per-verb fact — which verbs *consume* the subject model — since nothing in the manifest states it today; deriving it from the inherited option cannot. **Re-open with** MG10, which is the same question about payload size from the other end.

## 2. Deferred — with re-open triggers

- **MG1 — MCP resources (`resources/list`, `resources/templates/list`, `resources/read`).** The `dm:///` URI space (`dm:///help/{target}/{op}`, `dm:///schema/{target}/{op}`, `dm:///operators`, …) is designed but not served. It is a *second* implementation of content the tool surface already carries, and host support for `resources` has historically lagged `tools`, so the tool path is mandatory either way and the resource path buys host-side caching that nothing has measured a need for. **Re-open when** a target host is confirmed to read resources *and* a caller is re-fetching the same per-verb help often enough for caching to matter.

- **MG2 — MCP Apps (`io.modelcontextprotocol/ui`).** The in-chat HTML report widget that [`MODEL-REVIEW-GAPS.md`](MODEL-REVIEW-GAPS.md) §2 defers "when dmtool ships as an MCP server". Shipping the server fires that trigger; the widget itself is a separate extension, negotiated through capabilities and versioned independently. **Re-open when** the report surface is wanted in-chat rather than as a file.

### Hosting — the destination, not an afterthought

*(Re-shaped 2026-08-06, then drained as the binding landed the same day. The single "a hosted transport" row understated this badly: the design record's own scope says the **hosted** transport is the one that carries the value and that the stdio server is a development and testing vehicle for it. The **sequencing** is nonetheless a recorded owner decision — "stdio-first; hosted is a later, separately justified phase", 2026-08-02 — so what is deferred is the next phase of the plan, not a side quest. The old row also collapsed three separable things, one of which is nearly free and one of which has no undo.)*

**The transport is built** (2026-08-06): `dmtool mcp --http` serves Streamable HTTP on a bound port, bounded-concurrent, reusing the dispatcher, the registry, and the invoker unchanged — the contract, its status mapping, and the concurrency posture are [MCP-SPEC](MCP-SPEC.md) §7. What is left is packaging and a platform.

**Candidate assessments — measured 2026-08-06.** These extend the 2026-08-03 set in the [proposal](archived/MCP-SUPPORT-PROPOSAL.md) Appendix A rather than replacing it; that appendix stays as the record of what was known then. **Target chosen by the owner: alwaysdata free tier.**

| candidate | verdict | what was measured |
|---|---|---|
| **alwaysdata free** (chosen) | **viable for a demonstration endpoint** | Its *user program* site type is the fit: the platform assigns the address and the program must bind **`$IP` and `$PORT`** — the older `ALWAYSDATA_HTTPD_*` variables are gone, and for user-program sites the `IP` may be **IPv6**. Passes **H1 by construction** (a fixed €0 plan with no payment instrument registered, so the maximum charge is €0 because there is no collection channel). Fails **H11** — the vendor may delete a free account at its discretion — so it is fine where a redeploy is the whole cost and wrong as customer infrastructure. **H10 needs care:** three days of rolling backups mean anything written to disk outlives the request, which is survivable only because a call's tree is deleted before the call answers. **Still unverified, and only a deployment settles it:** an account without a payment instrument sits in *restricted mode*, whose "stricter filter rules" are unspecified — and an endpoint receiving automated agent traffic is plausibly what such rules exist to catch |
| **Cloudflare free** | **rejected — architecturally, not on policy** | **Workers Free** satisfies the billing bar outright: 100,000 requests/day, and on exceeding it the platform bypasses the Worker or returns a 1027 page with **no automatic billing** (H1 and H3 hold). It cannot run this server: Workers execute **JavaScript/WASM only**, so a native binary has no runtime there. Two further limits would bind even if the language matched — **10 ms CPU per invocation**, against a binary whose *startup alone* is ~37 ms, and **128 MB** per isolate against H7's floor. **Containers** are *"not available on the Free plan"* (minimum Workers Paid $5/month) and bill per GiB-second and vCPU-second beyond the included allowance, which is the usage-metered-with-an-uncapped-invoice class H1 disqualifies as a class rather than as a vendor. Serving a subset from Workers would mean a **second implementation** in JS/WASM over the interpreter, and it would lose the kernel oracle — a different product, not this transport |

- **MG12 — S2: publish a container image the customer runs in their own tenancy.** The design record's own answer to "can we have it hosted" — and it is **licensing-neutral**: shipping an image is Distribution exactly as shipping the binary already is, so [`LICENSING.md`](LICENSING.md)'s existing posture covers it unchanged. No ops burden, and it answers EU sovereignty *better* than we-host, because a customer who cares about sovereignty wants the thing in their own tenancy. Needs a `linux/amd64` build (the maintainer's machine is ARM), and a pinned `-Xmx` below the container limit — measured: authoring and inspection are flat at **~43 MiB**, document evaluation reached **519 MiB** on a 714 KB / 100-row stress fixture, so 256 MB carries ~6× headroom for authoring and must not be promised for evaluation. **Re-open when** a customer asks to run it themselves.

- **MG13 — S3: we host it.** The one with a consequence that cannot be undone: hosting counts as Distribution and/or Communication under **EUPL Article 1** ("providing access to its essential functionalities"), so the hosted combined work must be offered under **EUPL-1.2 with a maintained source repository** even though it hands out no copies — an obligation neither the local binary nor S2 carries. Data protection is the easier half and content-carrying already reduces it: holding nothing between requests makes the operator a processor only for a request's duration, with no retention policy, no deletion duty, and no storage to breach. The requirement set is H1–H12 in the [proposal](archived/MCP-SUPPORT-PROPOSAL.md) §13.3 — **H1 first: never silently enter a paid tier**, a ceiling by construction rather than by alerting, which already disqualified one candidate class outright (usage-metered serverless with an uncapped invoice). **Re-open only by an explicit owner decision**, and take the licensing call before any code.

- **MG4 — an MCP arm for the self-sufficiency eval.** [`EVAL-SPEC.md`](EVAL-SPEC.md) §2a's *bare-tool* arm means the CLI without the skill; it is not an MCP arm, and the harness drives `${CLI}` command forms throughout. So how much judgment an MCP-only caller loses — the residue no registry can derive: polarity, the *is this even a rule?* gate, the per-row-versus-aggregate recasting trap — is **unmeasured**, and the tool descriptions' sufficiency is an assumption. **Re-open when** that question is worth the harness work and the run cost.

- **MG6 — in-flight cancellation.** `notifications/cancelled` is accepted and produces no further messages for the request, which satisfies the MUST trivially over stdio: the reader is blocked inside the verb, so the notification is read only after the result was written. Over HTTP the transport-level signal is the client closing the response stream, which this server does not observe either. Actually *interrupting* work needs a cancellation-aware invoker in both cases. **Re-open when** a verb slow enough to be worth cancelling exists, or when a hosted caller needs to reclaim a worker it has abandoned.

- **MG7 — the closed-world verbs, behind an authority assertion.** `model rename` and the four `workspace` verbs are not served (MCP-SPEC §5). The design that would reach them is a caller-declared **authority assertion**: the request states that the supplied tree is an authoritative complete workspace, and a verb whose correctness depends on input-set completeness runs only under it and is **refused** without it — never silently degraded. **Re-open when** a caller needs a workspace-scoped answer, or with the hosting phase, where a carried resource tree makes the assertion natural.

- **MG8 — carried directory content.** A content parameter that takes a *directory* (the two custom-JS dirs) is refused. *(Reason corrected 2026-08-06: it was stated as "carrying a tree is a different shape", which is false on its face — a request already carries a whole workspace, one subject plus N `references`, and `McpToolCallTest` proves a multi-model subject resolves and validates.)* **The real discriminator is where an artifact's identity lives.** A document model carries its own inside the content — `header.id`, which `ReferenceResolvers` indexes on — so the server names every carried file itself and no caller-supplied name reaches the filesystem. A custom-JS implementation has no such id: its identity **is** the file name (`<Name>.js` registers the condition or type named `Name`). Carrying that set therefore means accepting caller-supplied name components, which is the one thing this surface refuses everywhere, so it needs a validated namespace rather than the existing content mechanism. That refusal is currently also what keeps `CustomJsWorker`'s per-call shutdown hook and its long-lived `node` child unreachable from a session, so **serving directory content re-opens the residency work with it** — the hook must be removed and the worker closed per call before a resident server may reach it. The two are one row because they cannot be shipped apart: implementing the carried tree removes the very thing keeping the leak unreachable. **Re-open when** a caller needs a custom condition or field type evaluated over MCP — and then fix the lifetime in the same change.

- **MG9 — the closed-world denominator is unaudited.** Five leaves are known to need input-set completeness. Whether any *other* verb makes a claim quantified over its input set has not been established by enumeration, so the exclusion list rests on the two mechanisms found rather than on a sweep. **Re-open** before MG7 is built, since the assertion needs the true denominator.

## 3. Out of scope

- **Any `2025-11-25` compatibility path.** No `initialize` handling beyond the corrective refusal, and no negotiated downgrade. A partly-served older client is the failure mode this project rejects outright; the refusal is legible and names where the supported set is published.

- **Multi round-trip requests (`resultType: "input_required"`), `subscriptions/listen`, sampling, roots, logging, and the tasks extension.** All are server-initiated or session-shaped interaction this surface does not need: every call is self-contained, and there is nothing to ask the caller mid-request.

- **Any new dependency.** Not an MCP SDK (none implements this revision), not a JSON-RPC library, not a runtime JSON-Schema validator. This also excludes wiring the MCP Inspector into CI: it is a per-method smoke tool, and the wire tests catch a broken frame or a missing method deterministically and in-process, so it would buy nothing and cost a Node dependency in the surface whose headline decision is zero new dependencies.

- **A local-convenience framing.** The positioning at the top of [`MCP-SPEC.md`](MCP-SPEC.md) forbids recommending MCP where the binary can be run. This is out of scope as a *documentation stance*, not merely unbuilt.
