# dmtool CLI conformance — gaps

> **What this is.** Open and deferred gaps on the **agent-facing conformance axis** — the *self-explain* + *diagnostic* contract that [`CLI-CONFORMANCE-SPEC.md`](CLI-CONFORMANCE-SPEC.md) owns (its sibling spec [`CLI-SPEC.md`](CLI-SPEC.md) owns the verb surface + safety gate). It is the CLI-conformance peer of [`FEATURE-GAPS.md`](FEATURE-GAPS.md): that tracker holds the **BA-authoring** ergonomics of the BA+agent loop, while this one holds what a *cold agent* needs to **select, risk-assess, and recover from** a verb using the tool's own output.
>
> **Lifecycle.** Same `-GAPS` discipline as its siblings ([`DEV-API-GAPS.md`](DEV-API-GAPS.md), [`INTERPRETER-GAPS.md`](INTERPRETER-GAPS.md), …): a gap lives here only while open — §1 open, §2 deferred (with re-open triggers), §3 out of scope. A shipped gap is **deleted**, not kept as a "shipped" list (git is the *what/when*; the graduated `CLI-CONFORMANCE-SPEC` matrix column / `CLI-SPEC` section is the *why*).
>
> **Current state.** §1 was drained and is **re-opened 2026-07-31** by external field feedback. The lesson is about this ledger's own axis: the guards here were **presence-shaped, not property-shaped** — the matrix asks "is there a description?", never "is it true?"; the `--text` guard covered three verbs; the catalog guard verified only the examples that exist. Three harnesses had additionally *encoded* the defective output (demo captures, probe gold, the test-side kernel projection), so they defended it rather than catching it. The rows are the resulting guard + instrument gaps; the public-contract half is designed in [`RESULT-CONTRACT-PROPOSAL.md`](archived/RESULT-CONTRACT-PROPOSAL.md). The earlier **2026-07-21 cold-agent probe** found the two candidate axes in §2 largely self-explaining already, so both stay demoted there with the evidence rather than built; two of its sub-findings shipped directly as one-line `--help` fixes, recorded in git.
>
> **Provenance.** A 2026-06-28 review of dmtool against a general "CLI tools for LLM agents" best-practices note found that dmtool already meets or beats ~80% of it — JSON-default output, a picocli-**derived** manifest that can't drift, the result envelope, the `refused`/referrers safety gate, the exit-code taxonomy, CI-executed examples. The rows below are the residual deltas, and — in §2/§3 — the ones we considered and are **not** taking, each with a re-open trigger so the decision carries its own expiry.

## 1. Open

Re-opened **2026-07-31** by external field feedback whose defects this ledger's own guards structurally could not see. The contract half is designed in [`RESULT-CONTRACT-PROPOSAL.md`](archived/RESULT-CONTRACT-PROPOSAL.md) and tracked by its acceptance gate; the rows below are the **guard and instrument** gaps that let the defects ship, plus the independent surface fixes. Each graduates into `CLI-CONFORMANCE-SPEC` as a matrix column or into the named spec, and is deleted here on ship.

### CG2 — rejection-claim coverage does not span all agent-facing catalog prose <a id="cg2"></a>

**The concrete plural-lookup defect is fixed, but the completeness gap remains.** Primary `invalidExample` and plural, code-keyed, kernel-executed `correctives[]` now form one rejection-evidence set for catalog lookup, enrichment, and span fallback; every literal `MVK_*` claim in `gotchas[].text` must have such evidence or a construct-independent `StructuralKernelFix`, and the shipped `HoursFromTime(Today)` miss is the live regression. That denominator is deliberately narrower than the original row's “every operator-specific rejection observation”: `constraints` also publish code-bearing rejection claims, and some gotchas say “rejected” without naming a code. Deleting this row on the narrower guard would overstate coverage. Close it only when an independently derived denominator spans every agent-facing rejection claim (`meaning`, `constraints`, and gotchas, including codeless wording), each claim has executable evidence keyed by operator + trigger + code + consumer context or a reasoned non-catalog classification, and the same audit helper rejects a synthetic unclassified claim. The earlier proposal to add `invalidExamples[]` is withdrawn: `correctives[]` was already the needed plural shape; incomplete consumers were the concrete defect.

### CG3 — the eval cannot see the runtime or text surfaces <a id="cg3"></a>

**The eval cannot see the runtime or text surfaces at all.** **Zero** `eval/tasks/` files invoke `model compute`, `model eval`, `rule eval`, or `--text`, and the harness scores task success against a gold rather than envelope conformance — so four of the shipped defects were live during the last full run (2026-07-09) and invisible to it. Add runtime-verb coverage and a bare-tool discovery task whose intent is "test this computation without modifying the model" *without* naming `--dry-run`; extend `gap-finder.workflow.js` to try plausible-but-absent sibling verbs (it audits descriptions today and never guesses). Correct `eval/TASKS.md`'s stale `schema add` reference. Contract properties stay in deterministic guards — they do not justify repeated LLM runs. Graduates to [`EVAL-SPEC`](EVAL-SPEC.md).

### CG4 — every `ResultEnvelope` factory opens with three adjacent `String`s <a id="cg4"></a>

**Every `ResultEnvelope` factory still opens with three adjacent `String`s — a design call, not an oversight, and it needs one.** `(target, op, summary)` is precisely the shape the project's long-parameter-list rule calls worst (several same-typed parameters, silently swap-prone), and it is the shape whose `boolean valid` neighbour produced the seven fabricated verdicts in the first place; the builder rule was cited to justify the *private* `Draft` while the public surface kept the smell. Two fixes, differently sized. A value object for the pair (`Verb.of("field","read")`) touches ~150 call sites, leaves `summary` adjacent anyway, and makes every call noisier — it relocates the smell. **Deriving** the identity from the live picocli spec, so a verb never states its own name, makes the swap *unrepresentable* — the outcome the style rules prefer — but is a cross-cutting change to every factory plus the shared `BaseCommand` helpers that hold no command instance. **Owner call needed on which.** Meanwhile the invariant is checked rather than assumed: `VerbDemonstrationTest` asserts every demonstrated verb's envelope echoes its own command path (63 verbs; does-fire-verified), so a swap fails the build even though it compiles. Graduates into `CLI-SPEC` §3 once decided.

  **Reviewed 2026-08-01 — measured, with a recommendation the owner still has to ratify.** Surface: **12 factory names / 17 public overloads**, **75** production call sites in 46 files (`queryResult` 30 · `rejected` 14 · `applied` 10 · `refused` 5 · `consistencyVerdict` 4 · `preview` 3 · `runtimeObservation` 3 · `staged` 2 · one each for `transaction`/`comparisonResult`/`dispatchCompleted`/`internalError`), plus 26 test calls, so the signature migration is 101 calls in 49 files; a full "a verb never states its own name" propagation reaches ~210 identity-bearing expressions in 77 files (the 75 direct + 33 `ModelWrite.of` + 92 shared-helper + the exception seams). **The deciding fact: picocli derivation is NOT total.** One `meta` `CommandSpec` yields both `meta/read` and `meta/modify` by option; `apply` publishes `apply/run` for the transaction while its per-op envelopes come from `ApplyCommand.Op`/validated op records; `where-used`/`batch`/`apply` publish synthetic `read`/`run` operations that are not picocli subcommands; and `Cli`'s `Throwable` seam has no `ParseResult` at all and deliberately falls back to `model/""`. So pure derivation needs a fallback — which is most of what made it attractive. Recommended instead: an **opaque `ResultIdentity`** parameter (so `summary` cannot swap with either component), derived from picocli where that mapping is total and obtained from closed typed sources — the `Op` enum, the validated op record — elsewhere, with **no** `ResultIdentity.of(String,String)` to relocate the smell into. Behaviour-neutral if the emitted `target`/`op`/`summary` are preserved exactly; the 63-route guard plus fixtures for `apply`, `batch`, both `meta` modes, `where-used` and both exception branches is the proof. *The static-seam count in the row above was wrong twice: I reported "four sites, three `rejected` + one `internalError`" from a grep pre-filtered to those two names and then stated it as a total; a reviewer corrected it to "two `rejected`, one `refused`, one `internalError`", also wrong. The enumeration without a pre-filter is **7 sites in `BaseCommand`, none in `Cli`**: 3 `rejected`, 2 `refused`, 1 `internalError`, 1 `queryResult`. A completeness claim is only as good as the search behind it, and neither of us stated the recall limit.*

### CG7 — no probe task exercises per-row computed identity <a id="cg7"></a>

**A probe task should make a repeated `model compute` result identify `VALUE`/`CLEARED`/`ERRORED` rows from its own output.** No current task exercises per-row computed identity, so the contract's most easily-misread output has no cold-agent evidence. Must run after a fresh native build. Graduates to [`PROBE-SPEC`](PROBE-SPEC.md).

## 2. Deferred — with re-open triggers

- **Per-verb `sideEffect` / `readOnly` axis in the manifest.** *(Demoted from open — 2026-07-21 cold-agent probe.)* Side-effect proved **reliably inferable** for 5/6 sampled verbs from `--help` alone (a `--dry-run`/`-o` flag + prose like "write the model back" vs "into `data`"), so a full typed `SideEffect` enum + manifest field + a matrix gate across ~50 verbs is **not yet justified**. The one blind spot found — `field modify`'s retype-cascade on dependent rules — was closed directly in `--help`. **Re-open when** a fuller probe/eval shows an agent actually mis-judging a verb's blast radius, or a safety incident argues for making the inferred axis explicit (it's a guardrail, so the bar to proceed is lower than for a pure-clarity feature).

- **`doNotUseWhen` on near-sibling verbs.** *(Demoted from open — 2026-07-21 cold-agent probe.)* The proposed sibling groups (`model read` ↔ `export`, `check` / `eval` / `compute`, `apply` ↔ `batch`) already **disambiguate cleanly** from `--help`. The only ambiguity found — `rule eval` ↔ `model eval --rule` — was fixed directly with a one-line cross-reference in each description. **Re-open when** the gap-finder recurrently flags an `AMBIGUOUS_MODE` sibling pair a description tweak can't resolve — then the structured `doNotUseWhen` + `AP7` matrix column earns its keep.

- **Per-verb `emits[]` (the failure space, discoverable *per verb*).** The failure space is already discoverable **reactively** — every `RK_*` / `MVK_*` code the tool emits resolves in the `diagnostics` catalog (`diagnostics` list + `diagnostics <CODE>`), each carrying a `fix`. A per-verb `emits[]` would add **proactive** planning ("what could this verb return before I run it"), but it is **not** picocli-derivable — it needs a verb→codes source that does not exist yet. This is the flip side of the `CLI-SPEC` §2 correction that removed the premature "each op advertises `emits[]` in the manifest" claim. **Re-open when** a planning or apply-the-fix consumer needs the per-verb failure space proactively, or a probe shows agents failing to anticipate a verb's errors — likely then a **proposal**, since the verb→codes derivation carries real design risk.

- **A runnable next-action command on `refused`.** The `refused` envelope already carries the referrers (in `data`) and a `fix` diagnostic; emitting the *exact* remediation invocation (e.g. the `remove --cascade` line to run) is the note's "include next actions." **Re-open when** a fix-applying harness exists to consume it, or a probe shows agents failing to recover from `refused` despite referrers + `fix`.

- **Error-classification booleans (`retryable` / `correctableByAgent` / `userActionRequired`).** For dmtool these would be near-constant — the real signal already lives in `outcome` + `source` + presence-of-`fix`, and the one distinction that matters (a cascade *decision* vs a tool bug) is already encoded in `outcome`/exit-code. **Re-open when** an apply-the-fix harness actually consumes them (the same consumer-exists discipline that withheld a machine `suggest` field).

- **An envelope `version` field.** The note warns against unversioned output-shape drift. dmtool's whole envelope contract is **derived + drift-guarded** (`SchemaVerbTest`, `result.schema`), so an embedded version buys little today. **Re-open if** the envelope must change incompatibly, or an external consumer pins the shape and needs a version to negotiate against.

- **A cross-verb stdout-purity guard ("nothing but one JSON document").** The **error path** is already broadly guarded — `DiagnosticConformanceFuzzTest` parses stdout and asserts a structured envelope across ≥10 verbs. A guard covering the *success* + `--text` path for every verb is cheap insurance, but this spec is deliberately **grounded in observed misses**, and no stdout contamination has been observed. **Re-open when** any verb is seen emitting non-JSON on stdout in a machine mode.

## 3. Out of scope — the remote / async operation model

A cluster of the note's recommendations presuppose a **resident or remote** tool: idempotency keys (§14), long-running operations with `operationId` / resume / poll (§15), the preview-id + confirmation-token lifecycle (§13), profiles / `--target-env` / auth status (§16), `--trace-id` + a correlated audit log (§16/§21), and cursor/pagination for large result sets (§17). dmtool is **local, synchronous, single-file, stateless-per-call** — the model file is the durable state, and git is the audit trail + undo. These recommendations **void** unless a resident mode lands, and that mode — **`dmtool serve`** — is already an examined **non-goal with its own re-open triggers** in [`FEATURE-GAPS.md`](FEATURE-GAPS.md) §4. They are pointed at, not re-litigated here.
