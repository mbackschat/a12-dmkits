# dmtool CLI conformance — gaps

> **What this is.** Open and deferred gaps on the **agent-facing conformance axis** — the *self-explain* + *diagnostic* contract that [`CLI-CONFORMANCE-SPEC.md`](CLI-CONFORMANCE-SPEC.md) owns (its sibling spec [`CLI-SPEC.md`](CLI-SPEC.md) owns the verb surface + safety gate). It is the CLI-conformance peer of [`FEATURE-GAPS.md`](FEATURE-GAPS.md): that tracker holds the **BA-authoring** ergonomics of the BA+agent loop, while this one holds what a *cold agent* needs to **select, risk-assess, and recover from** a verb using the tool's own output.
>
> **Lifecycle.** Same `-GAPS` discipline as its siblings ([`DEV-API-GAPS.md`](DEV-API-GAPS.md), [`INTERPRETER-GAPS.md`](INTERPRETER-GAPS.md), …): a gap lives here only while open — §1 open, §2 deferred (with re-open triggers), §3 out of scope. A shipped gap is **deleted**, not kept as a "shipped" list (git is the *what/when*; the graduated `CLI-CONFORMANCE-SPEC` matrix column / `CLI-SPEC` section is the *why*).
>
> **Current state.** No open gaps. >
> **Provenance.** A 2026-06-28 review of dmtool against a general "CLI tools for LLM agents" best-practices note found that dmtool already meets or beats ~80% of it — JSON-default output, a picocli-**derived** manifest that can't drift, the result envelope, the `refused`/referrers safety gate, the exit-code taxonomy, CI-executed examples. ## 1. Open

> **The rows below are what remains of one 2026-08-14 cross-component audit**, sharing a root cause with [IF287](INTERPRETER-FINDINGS.md#if287)'s interpreter defects: a condition operand may name a GROUP, which the kernel expands recursively to every field below it, and **expansion is opt-in at every site that resolves an operand**. The kernel primitive is correct and documents the consequence itself — `KernelAdapter.whereUsed` says *"'Direct' is exact: a rule that references an enclosing group is not listed for a field inside it"* — so every defect here is a **caller treating "not directly referenced" as "not referenced"**, or an expansion losing the star that makes it span rows.
>
> The audit's central prediction is now an observation: removing a field read only through its group returned `outcome: applied`, `verification: KERNEL_CONFIRMED`, `written: true`, no diagnostics, because the rule still names a group that still exists and the terminal kernel check has nothing to object to. Its complementary correction is worth carrying too — removing a field a rule names DIRECTLY was never data loss, since that rule dangles and the kernel rejects the write. **The group-reached direction is the whole defect.**

- **CG18 — `field`/`group move` has no reference check, and `ReferenceRewriter` advertises a refusal it never makes.** Split from CG13's delete half because it asks a different question. A delete gate asks "is anything reading this?"; a MOVE does not remove the field, it changes **which group-operand expansions include it**. Moving `/Order/ShippingAddress/Street` into `/Order/Billing` silently drops it from `AllFieldsFilled(/Order/ShippingAddress)` and silently adds it to any operand over `/Order/Billing` — no condition text mentions the field, so there is nothing to rewrite, the model stays kernel-valid, and `changed.rewroteReferences: []` is literally true while being maximally misleading (`StructureRefactor.java:120-130`). Separately, `ReferenceRewriter.java:26-27` **states** that a `*`-reference a rename would dangle must be refused; no such check exists, and a repeatable group operand IS a `*` reference — "advertise nothing you cannot point at", with the advertisement already in the source. **Actionable work:** measure whether the membership change is runtime-observable (near-certain, but it is a runtime claim and wants the differential, not a source read), then choose the treatment — a refusal is probably wrong, since the move is legal and usually intended, so an ADVISORY naming which operands gain and lose the field is the likely answer. That choice is a design call to state rather than assume. **Completion gate:** a move that changes a group operand's membership either refuses or reports it in `changed`; the `ReferenceRewriter` claim is enforced or deleted; and a move that changes no membership stays silent.

- **CG15 — the converter's group arms that still report *unsupported* or lose a star.** The mixed group+field field-fill arm is done (its expansion keeps the star on both arms, `adapter.MixedScopeStarPreservationTest`); these remain, and **each needs its kernel admission measured first** — [KF187](KERNEL-FINDINGS.md#kf187) already covers several carriers, so check it before probing. `ConditionConverter:1269-1280` rebuilds a starred group plus a declared tail carrying no `*`, so a nested repeatable under a starred group is pinned to row 1. A kernel-legal **non-repeatable** group operand makes `flatten` throw and is reported as "converter error". `.filter(kind == NUMBER)` at `:1273` silently narrows a mixed-kind group. `:1147` converts `NumberOfFilledGroups(Group*)` through `model.group(e.getFullName())`, dropping the star its own comment promises ("a single repeatable group, all reps") — the round trip then renders the unstarred form the kernel REJECTS (`MVK_NO_WILDCARD`), so it is loud on write-back but still wrong in `rule read` output, and it needs the typed surface too, since `Dsl.numberOfFilledGroups` takes a `GroupRef` that carries no star. The group arms of `NumberOfValueInFields` (`:1122-1128`), `NumberOfFilledFields` (`:1172-1186`) and `FieldValuesNotUnique` (`:396/473/488`) report *unsupported* for shapes KF187 measures the kernel as ADMITTING, and a mixed list whose first entity is a field mislabels a converter gap as "unresolved reference" (`:440-448` vs `isFieldFillQuantifier` `:513-519`). **Completion gate:** a round-trip row proves each converted group operand renders back to the authored condition.

- **CG16 — the diff/suggest surfaces still read references exactly where they mean reachability.** The readers are done (`KernelAdapter.referrersReaching`/`isReadByAnything` behind `model usage`, `ModelReport`'s dead-field set, `FieldDiffProjector`, and `field modify`'s retype advisory). These three were deliberately left out of that slice, since its completion gate named the readers and the doc claim: `ModelDiff.java:175-181` passes referrers to the FIELD arm only, so a removed group that rules directly reference never gets `REFERENCED_ELEMENT_REMOVED`; `RelocationMatcher.refsOf` (`:149-153`) discards `groupPaths()`, so `groupRefactors` (`ModelDiff.java:409-443`) can never emit a group rename/move; and `rule check --suggest-error-field` (`RuleCheckCommand.java:188-195`) tells the author "the condition references no field inside its iteration scope" when every operand is a group, steering them off the only valid picks. **One claim here is UNMEASURED and must not be repeated as fact until it is:** that `rule deps`/`rule explain` disagree with `where-used`. Half of it is settled by reading — `RuleDepsCommand:83` projects the CONVERTED AST while `where-used` reads the kernel primitive, so the "same primitive backs both" premise is false and both javadocs now say so — but whether the two therefore produce different ANSWERS was never probed. **Completion gate:** a removed group with direct referrers reports `REFERENCED_ELEMENT_REMOVED`, a group rename is emitted, `--suggest-error-field` offers a valid pick for an all-group condition, and the `rule deps` question carries a measurement either way.

## 2. Deferred — with re-open triggers

- **`doNotUseWhen` on near-sibling verbs.** *(Demoted from open — 2026-07-21 cold-agent probe.)* The proposed sibling groups (`model read` ↔ `export`, `check` / `eval` / `compute`, `apply` ↔ `batch`) already **disambiguate cleanly** from `--help`. The only ambiguity found — `rule eval` ↔ `model eval --rule` — was fixed directly with a one-line cross-reference in each description. **Re-open when** the gap-finder recurrently flags an `AMBIGUOUS_MODE` sibling pair a description tweak can't resolve — then the structured `doNotUseWhen` + `AP7` matrix column earns its keep.

- **Per-verb `emits[]` (the failure space, discoverable *per verb*).** The failure space is already discoverable **reactively** — every `RK_*` / `MVK_*` code the tool emits resolves in the `diagnostics` catalog (`diagnostics` list + `diagnostics <CODE>`), each carrying a `fix`. A per-verb `emits[]` would add **proactive** planning ("what could this verb return before I run it"), but it is **not** picocli-derivable — it needs a verb→codes source that does not exist yet. This is the flip side of the `CLI-SPEC` §2 correction that removed the premature "each op advertises `emits[]` in the manifest" claim. **Re-open when** a planning or apply-the-fix consumer needs the per-verb failure space proactively, or a probe shows agents failing to anticipate a verb's errors — likely then a **proposal**, since the verb→codes derivation carries real design risk.

- **A runnable next-action command on `refused`.** The `refused` envelope already carries the referrers (in `data`) and a `fix` diagnostic; emitting the *exact* remediation invocation (e.g. the `remove --cascade` line to run) is the note's "include next actions." **Re-open when** a fix-applying harness exists to consume it, or a probe shows agents failing to recover from `refused` despite referrers + `fix`.

- **Error-classification booleans (`retryable` / `correctableByAgent` / `userActionRequired`).** For dmtool these would be near-constant — the real signal already lives in `outcome` + `source` + presence-of-`fix`, and the one distinction that matters (a cascade *decision* vs a tool bug) is already encoded in `outcome`/exit-code. **Re-open when** an apply-the-fix harness actually consumes them (the same consumer-exists discipline that withheld a machine `suggest` field).

- **An envelope `version` field.** The note warns against unversioned output-shape drift. dmtool's whole envelope contract is **derived + drift-guarded** (`SchemaVerbTest`, `result.schema`), so an embedded version buys little today. **Re-open if** the envelope must change incompatibly, or an external consumer pins the shape and needs a version to negotiate against.

- **A cross-verb stdout-purity guard ("nothing but one JSON document").** *(Corrected 2026-08-03: the earlier entry rested on “not observed” and overstated the unguarded surface.)* A strict process-boundary sweep ran one canonical successful route for all **81 live leaves**: **79 JSON-promising routes** emitted exactly one JSON value with EOF immediately after it; bare `schema` deliberately emitted orientation text and `export card` deliberately emitted Markdown. The argument-dependent `export --out-dir` route also deliberately exits 0 with empty stdout while writing its four artifacts. The **error path** remains broadly guarded by `DiagnosticConformanceFuzzTest`, and `InternalErrorBoundaryTest` specifically locks an unexpected throwable to one structured error envelope on stdout with the trace on stderr. `VerbDemonstrationTest` now guards `--text` totality across the demonstrated envelope-producing success surface; `--text` is intentionally human text, not machine JSON. The remaining deferral is therefore narrower: there is no permanent route-class-aware strict parse-to-EOF guard over every success argument mode. **Re-open when** a JSON-promising route is seen contaminating stdout, or a consumer needs that stronger permanent coverage.

## 3. Out of scope — the remote / async operation model

A cluster of the note's recommendations presuppose a **resident or remote** tool: idempotency keys (§14), long-running operations with `operationId` / resume / poll (§15), the preview-id + confirmation-token lifecycle (§13), profiles / `--target-env` / auth status (§16), `--trace-id` + a correlated audit log (§16/§21), and cursor/pagination for large result sets (§17). dmtool is **local, synchronous, single-file, stateless-per-call** — the model file is the durable state, and git is the audit trail + undo. These recommendations **void** unless a resident mode lands, and that mode — **`dmtool serve`** — is already an examined **non-goal with its own re-open triggers** in [`FEATURE-GAPS.md`](FEATURE-GAPS.md) §4. They are pointed at, not re-litigated here.
