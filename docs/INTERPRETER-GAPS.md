## 1. Open

- **IG178 — a padded or blank `sValue` is declined** (opened 2026-10-21, [KF574](KERNEL-FINDINGS.md#kf574)). A12 admits it by its trim and stages the text as written, filled and without a formal check; `ModelLoader` refuses the model as unsupported rather than staging a value its own formal gate, the identity gate and `Document`'s value resolution would each reject. It settles by carrying a staged cell past those three gates, locked by the two KF574 rows. It blocks no consumer known today.
- **IG175 — a boolean model member A12 cannot bind is read as off** (opened 2026-10-21, cold review). `ConfigFlag.UNREADABLE` says folding it into `OFF` evaluates a model the Kernel never loads, and every reader, in `ModelLoader` and `IncludeAssembly`, still compares with `ConfigFlag.ON`, so `"positivesOnly": "yes"`, `1.5` or `{}` loads as unset and evaluates. It is over-admission only, of a model `checkConsistency` refuses ([KF569](KERNEL-FINDINGS.md#kf569)). It settles by refusing the model at load, with a law row that A12 refuses the same member values.
- **IG176 — the evaluation clock is proleptic Gregorian, A12's is the Julian–Gregorian hybrid** (opened 2026-10-21, cold review). `EvalClock.at` converts the instant with a proleptic day count, while A12 sets a `GregorianCalendar` in the model's zone, which switches to Julian before 1582-10-15; `EvalClockAtTest`'s rows are hand-derived. An instant such as 1500-03-10T12:00Z gives `Today` days apart. It affects only a pinned instant, `evaluationInstant` or dmtool's `--clock`, that far back, and settles by oracling `EvalClock.at` against `GregorianCalendar` on the JVM, reusing `DateCalendarBasis.LEGACY_HYBRID` if they differ.
- **IG177 — the non-ASCII digit set is the platform's** (opened 2026-10-21, cold review). Number ingress converts every decimal digit `Char.isDigit` accepts, which the JVM answers from `Character` and Kotlin/JS from its own Unicode table, so a release skew between the two would read one digit differently. The measured rows agree on the JVM ([KF564](KERNEL-FINDINGS.md#kf564)). It settles with a commonTest that enumerates the BMP decimal digits on both and compares them with the JVM's set.
- **IG166 — the format-keyed computation store was measured on TIME-kind targets only** (opened 2026-10-13, cold review). [IF397](INTERPRETER-FINDINGS.md#if397) routes every temporal store through `dateStoreFormat`, so it also changes a DATE_TIME-kind target declared `dd.MM.yyyy` and a DATE-kind target declared with a date-time format, neither run against A12. Settles with those two rows in `adapter.laws.FirstFilledDateCrossKindTargetDiffTest`.
- **IG167 — three message-fault shapes are unmeasured** (opened 2026-10-13, cold review). The interpreter renders only the requested locale's text, so a key token that selects no row in another locale's text never faults, and an empty or formally invalid FIELD key in a `.value` token raises `UnmatchedMessageKeyFailure`; A12 is measured on neither. [KF561](KERNEL-FINDINGS.md#kf561)'s "a level nothing binds renders its first row" rests on one carrier, a root rule with a keyed and a starred read. Settles with those rows in `adapter.laws.MessageParameterRowDiffTest`.
- **IG168 — several 2026-10-13 locks are weaker than their findings** (opened 2026-10-13, cold review). The required-empty read ([IF394](INTERPRETER-FINDINGS.md#if394)), the partial row domain ([IF395](INTERPRETER-FINDINGS.md#if395)) and the checked key value ([KF549](KERNEL-FINDINGS.md#kf549)) have no JVM/Node `commonTest` row; the base-view-first message order of `SPEC-2026-10-13-06` is unlocked because the differential compares sorted signatures; and two locks added in `83d726617` and `796e060e4` assert a `.take(1)` or a count where the finding states the values. Settles by adding the `commonTest` rows, one unsorted order assertion and value assertions.
- **IG169 — the read-side `authored` text has no observing control** (opened 2026-10-13, cold review). `Document.formalInput` hands the pre-fold text to `resolveValue`/`cellState`, but the validation and computation paths read (`DmInterpreter.kt` 799/991, `ComputationEngine.kt` 202) first consult `FormalResultCache`, which measures the authored text itself through `formalInputAt`. Replacing it with the folded text survived `adapter.laws.CheckedInputOrderDiffTest` (`scripts/mutant.sh`, 2026-10-13), whose CRLF row reaches the cell through both a rule and a computation. The same duplication reaches `storedValueOf`, which runs the input gates on a computed date although a computed value meets none of them (KF547); the cold review found no caller that hands it a value the gates refuse, without enumerating the callers. Settles with a read the cache does not gate, or by removing the duplicate gate.
- **IG170 — a perf record names HEAD, not the tree it measured** (opened 2026-10-13). `scripts/perf.sh` refuses only a dirty `perf-results/`, and the run record carries `commit` alone, so a gate run over uncommitted source is attributed to the commit before it. Record `2026-10-13T065211Z` reads `c223b0f4c` yet measured `abdc13a27`'s charset copy, committed 51 minutes later ([checkpoint](INTERPRETER-PERFORMANCE-RESULTS.md)). Settles with a source-tree state in the run record, or a refusal of a dirty source tree.
- **IG171 — the compute-overlay correlation lane's collections flip at a commit that does not change its work** (opened 2026-10-13). At n = 6000, collections in the window went from 0 to 7 to about 275, and the median from 146 to 151 ms to 152 to 155 ms, which breaches its 151.89 ms ceiling. Full gates with only the interpreter sources swapped place the flip between `e66cafa18` and `7b98fae62`, one run per point ([checkpoint](INTERPRETER-PERFORMANCE-RESULTS.md)). `7b98fae62` changes message rendering, and this lane renders only the template `x`; measured alone, its cost is unchanged. The owner accepted the deviation, and this lane's darwin anchor was raised from 91.45 to 94.6 ms, so the bar admits this mode with 0.8 % to spare and still catches anything beyond it. The n = 1500 point now breaches the same way (2026-10-21): 39.57 and 39.64 ms against its 39.18 ms ceiling in two of three gates at `76d8111a5`, 38.06 ms in the third, with 288 to 332 collections in the window against 161 at `d26873580`. Measured alone with a 120-run warmup, interleaved four times against `d26873580`, the lane costs 34.3 ms against 34.0 ms, so the gate's 4.5 % is the mode and not the work; the darwin n = 1500 anchor (23.14 ms) has not moved. Settles with a comparison of the `allocation` records the routine gate writes for this lane on either side of that commit, or a repeated bisection that names the mechanism.
- **IG179 — a correlated column holding one unavailable empty cell takes the nested tally, O(rows) per row** (opened 2026-10-21, [KF552](KERNEL-FINDINGS.md#kf552)). Both kernel strategies are quadratic on this shape too and the interpreter stays about 1.4× ahead of the generated Java ([checkpoint](INTERPRETER-PERFORMANCE-RESULTS.md)), so `RequiredColumnCorrelationPerfTest` holds it to the kernel's class rather than to the sub-quadratic floor. The keyed and ordered tallies are additive per kept row and are exact for every available row, so a scope could keep them and re-read only its unavailable rows nested, O(rows × unavailable rows). That would beat A12's own complexity rather than match it, and it has to settle three cases the indexed path never meets: the outer row itself unavailable under a self-exclusion, an unavailable join field, and the ordered plan. Settles with the owner's decision whether to go below the kernel's class here; a yes needs a differential over those three cases before it lands.
- **IG174 — a domain bound to a joined row is declined** (opened 2026-10-14, [IF402](INTERPRETER-FINDINGS.md#if402)). From a joined row the interpreter answers starred and keyed reads ranging at or above the common parent ([KF567](KERNEL-FINDINGS.md#kf567)) and stars below a joined group ([KF573](KERNEL-FINDINGS.md#kf573)), and refuses two shapes A12 admits: an unstarred group or field operand of a fill quantifier, and a bare-group scan. Each settles with a differential over matched and unmatched joined rows, which decides whether the unmatched side's `-5` row reads empty. It blocks no consumer known today.
- **IG173 — three edges of the Number ingress and bound printing are characterized, not matched** (opened 2026-10-14, [KF564](KERNEL-FINDINGS.md#kf564)). (a) A quoted `1e2147483648` converts in A12, its scale still fitting 32 bits, and then faults `validateFull` with an arithmetic underflow (a12-kernel-lean's capture); the interpreter keeps the text and reports `zahlHatUngueltigeZeichen`. (b) A converted value whose point shift exceeds the per-field decode ceiling, 16,000,000 places, is kept verbatim as a denial-of-service guard; A12 expands it, which exhausted the measuring JVM at `1e±2147483647`, so the rows between the ceiling and that point are unmeasured on A12's side and differ on ours. A zero there, such as `0e99999999`, is a plain `0` to A12 and kept text to us. (c) `printedNumberBound` rounds the double's shortest decimal, while A12 prints with Java's `%.nf`, whose digits come from an older binary-to-decimal conversion that can emit one more digit for a few doubles; a bound whose rounding position falls on that digit would print differently. No such bound is known. Each settles with one kernel row, (a) and (b) only if a consumer can author such a value through a supported route.
