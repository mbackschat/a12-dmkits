## 1. Open

- **IG170 — a perf record names HEAD, not the tree it measured** (opened 2026-10-13). `scripts/perf.sh` refuses only a dirty `perf-results/`, and the run record carries `commit` alone, so a gate run over uncommitted source is attributed to the commit before it. Record `2026-10-13T065211Z` reads `c223b0f4c` yet measured `abdc13a27`'s charset copy, committed 51 minutes later ([checkpoint](INTERPRETER-PERFORMANCE-RESULTS.md)). Settles with a source-tree state in the run record, or a refusal of a dirty source tree.
- **IG171 — the compute-overlay correlation lane's collections flip at a commit that does not change its work** (opened 2026-10-13). At n = 6000, collections in the window went from 0 to 7 to about 275, and the median from 146 to 151 ms to 152 to 155 ms, which breaches its 151.89 ms ceiling. Full gates with only the interpreter sources swapped place the flip between `e66cafa18` and `7b98fae62`, one run per point ([checkpoint](INTERPRETER-PERFORMANCE-RESULTS.md)). `7b98fae62` changes message rendering, and this lane renders only the template `x`; measured alone, its cost is unchanged. The owner accepted the deviation, and this lane's darwin anchor was raised from 91.45 to 94.6 ms, so the bar admits this mode with 0.8 % to spare and still catches anything beyond it. The n = 1500 point now breaches the same way (2026-10-21): 39.57 and 39.64 ms against its 39.18 ms ceiling in two of three gates at `76d8111a5`, 38.06 ms in the third, with 288 to 332 collections in the window against 161 at `d26873580`. Measured alone with a 120-run warmup, interleaved four times against `d26873580`, the lane costs 34.3 ms against 34.0 ms, so the gate's 4.5 % is the mode and not the work. The owner accepted it too, and the darwin n = 1500 anchor was raised from 23.14 to 24.59 ms, which admits the highest of six such gates (41.24 ms) with 0.8 % to spare. The n = 6000 point then breached once at `38dbea615`, 157.78 ms against 157.09 ms with 260 collections, and was left where the owner set it. A targeted run of the eleven new lane classes followed by this lane then measured 43.61 ms at n = 1500 (attempts 42.00, 43.61, 47.44 ms), past even the raised bar, so the lane's reading depends on what ran before it in the fork and a further raise would only chase that. Settles with a comparison of the `allocation` records the routine gate writes for this lane on either side of that commit, or a repeated bisection that names the mechanism.
- **IG179 — a correlated column holding one unavailable empty cell takes the nested tally, O(rows) per row** (opened 2026-10-21, [KF552](KERNEL-FINDINGS.md#kf552)). Both kernel strategies are quadratic on this shape too and the interpreter stays about 1.4× ahead of the generated Java ([checkpoint](INTERPRETER-PERFORMANCE-RESULTS.md)), so `RequiredColumnCorrelationPerfTest` holds it to the kernel's class rather than to the sub-quadratic floor. The keyed and ordered tallies are additive per kept row and are exact for every available row, so a scope could keep them and re-read only its unavailable rows nested, O(rows × unavailable rows). That would beat A12's own complexity rather than match it, and it has to settle three cases the indexed path never meets: the outer row itself unavailable under a self-exclusion, an unavailable join field, and the ordered plan. Settles with the owner's decision whether to go below the kernel's class here; a yes needs a differential over those three cases before it lands.
