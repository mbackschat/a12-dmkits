# interpreter — gaps

> **What this is** — the interpreter's peer of [`DEV-API-GAPS.md`](DEV-API-GAPS.md) and [`FEATURE-GAPS.md`](FEATURE-GAPS.md): the single tracking surface for **open `:interpreter` gaps, deferred items, and to-fix issues**. It exists so open work is easy to **track, report, and pick up** — and so [`INTERPRETER-FINDINGS.md`](INTERPRETER-FINDINGS.md) can be what a findings doc should be: **settled, verified knowhow** you read to warm up and not re-investigate (like `KERNEL-FINDINGS.md`), never a backlog of dispositions ("open / to fix / deferred"). Per the CLAUDE.md *"rationale is timeless; a disposition is status"* rule — the findings hold the timeless fact, this ledger holds the live status.
>
> **Lifecycle.** A gap is born here with an `IG<n>` code under the section matching its status (§1 open / §2 deferred / §3 out-of-scope). When it ships, three things happen **in the fix's own commit**: (1) its **rationale graduates to a numbered `IF<n>` finding** in [`INTERPRETER-FINDINGS.md`](INTERPRETER-FINDINGS.md) — that finding notes it "graduated from IGn"; (2) any code/test comment citing `IGn` is **repointed to `IFn`**; (3) the gap's row is **deleted from this ledger**. **There is no "fixed/shipped" section — we don't record fixed gaps.** A fixed gap is no longer a gap; **git is the history of *when/what* was fixed, and the `IFn` finding is the *why*** — a hand-kept "shipped" list would only duplicate both and rot. So this ledger only ever lists **live, unfinished work** (the already-shipped IF20-per-cell / IF21 / IF23 / IF24 / IF25 live as findings, not here). A **deferred** gap stays in §2 with its re-open trigger, and an **ongoing as-touched** refactor stays in §2 with its remaining-work note (it is progressing in increments, not parked — its shipped parts graduate to its `IF<n>` finding while the row stays until *all* of it lands); the technical detail of each gap lives in its cited `IF<n>` finding (the knowhow), this ledger holds only *what's left to do and why*.
>
> **Section invariant (the placement rule):** every section holds exactly one **live** status — **§1 = open, §2 = deferred / ongoing-incremental, §3 = out-of-scope**. A FULLY-shipped/graduated entry belongs in **none** of them: completing it *deletes* its row (see the lifecycle). So §1 reads `_None open._` whenever nothing is open — the marker every `-GAPS` ledger uses, so one grep rolls up the whole family (`GapLedgerTemplateGuardTest`) — and a fully-FIXED entry **anywhere** in this ledger is a bug in *this doc* — git already records the fix. (A partially-shipped *ongoing* refactor in §2 is not "fixed" — it stays until all of it lands.)
>
> **Current state.** §1 lists what is open; read it rather than this paragraph — IG144 had been parked for want of kernel value-tier rows, and the grid that supplied them also turned up its unreported mirror and one year-zero divergence. §2 carries the deferred rows with their re-open trigger or remaining work: **IG143** (a hand-built interpreter document is a route hybrid), **IG141** (DateRange shared-format declaration order), **IG137** (performance tooling and reporting residuals), **IG139** (the `group-star expansion @8000` lane is too noisy to carry an absolute bar), and **IG83** (portable timezone-id support, Route A); §3 carries the out-of-scope decisions. A **shipped** gap appears nowhere here: its rationale graduated to a numbered `IF<n>` finding that names the `IGn` it came from, so a code comment citing `IGn` resolves by grepping [`INTERPRETER-FINDINGS.md`](INTERPRETER-FINDINGS.md), with one measured exception: **`IG30`** (cited in `adapter/.../laws/MultiFieldAggregateDiffTest.kt`) predates that convention and names no finding, so its citation site carries the contract and git holds the row. A cold review's enumeration on 2026-08-24 found it; do not assume the sweep that found it covered other families.
>
> **Scope.** `:interpreter` only — the kernel-free Kotlin evaluator (parser, evaluation semantics, model loader, the differential/perf harnesses' interpreter side). dmkit (rulekit/modelkit/edit) authoring gaps go to [`DEV-API-GAPS.md`](DEV-API-GAPS.md); kernel-coverage classification stays in the MVK / RT-semantics / grammar ledgers.

## 1. Open

- **IG148 — the rule-message `$#…$` GROUP parameter is not implemented, so it survives into the rendered text verbatim** (measured 2026-09-05, kernel both strategies). The kernel renders the firing row's own 1-based repetition index, and `1` for a non-repeatable group ([KF245](KERNEL-FINDINGS.md#kf245)); the interpreter's message token pattern has no `$#…$` alternative at all, so a user reads `own=[$#/Claim/Lines$]` where the kernel gives `own=[2]`.

  **What the fix needs**, so it is not re-derived: an alternative in `eval/Message.kt`'s `tokenPattern`, a resolver reading the row coordinate off the `EvalContext` the way `CurrentRepetition` already does, the `RuleGroup`/`RootGroup` shorthands, and their bilingual spellings — a12-kernel-lean's `SPEC-2026-09-05-03` reports that the live keyword set follows the CONDITION language in both directions, so `LfdNr` is the German arm and that is their report, unmeasured here. Discovered by measuring their `SPEC-2026-09-05-02` rather than by a failing lane, because nothing exercised the position.

- **IG147 — an unresolvable temporal CONSTANT is classified on a different channel by each estate** (measured 2026-09-03, tri-engine). A DateTime constant naming a wall time the model's declared zone skips — `31.03.2024T02:30:00` under `Europe/Berlin` — makes the kernel produce **no computed outcome at all** and report one `berechnungsWertFehler` `VALUE_ERROR` per in-capacity target row in `formalErrorsInOperands` ([KF231](KERNEL-FINDINGS.md#kf231)). The interpreter instead reports the target as **ERRORED** carrying the canonicalized attempt `2024-03-31T02:30:00`. Both agree the cell has no valid value; they disagree about which channel says so, and `compute()`'s public result is where a consumer sees it.

  **Why this is filed rather than patched.** `DmInterpreter.compute` publishes three outcome buckets and no operand-error channel, so matching the kernel here means either growing that channel or reclassifying the case — a decision about the public compute contract, and adjacent to the standing compute-granularity ruling that result-envelope granularity is not behaviour-parity territory ([`CONFORMANCE-CORPUS-SPEC.md`](CONFORMANCE-CORPUS-SPEC.md) §7). The literal-typing half of the same measurement WAS fixed ([IF318](INTERPRETER-FINDINGS.md#if318)); this is the residue. Pinned meanwhile — including the exact interpreter shape, so the divergence cannot widen unnoticed — by `adapter.laws.DateTimeConstantZoneSplitDiffTest.theUnresolvableLabelIsClassifiedDifferentlyByTheTwoEstates`.

- **IG145 — the house comparison projection drops a repeatable GROUP node's own row index, so the differentials cannot see a finding attributed to the wrong descendant row** (measured 2026-08-31; **surface list corrected the same day, see below**). `formatPointer(path, reps)` indexes every segment *but the last*. `MessagePointerProjection` already documents that terminal-index loss and arranges itself around it — but around A12's message **sentinels** on a field's last segment, where the dropped value is never a row. What is new is the case where the last segment is a repeatable **group**: there the dropped coordinate is a real row index. Measured on a doubly over-limit document, the Kernel emits three `zuGrosseKontextnummer` findings at `/Billing/Invoices/Periods` with `[1,3,1]`, `[1,3,2]`, `[1,3,3]`, and all three render `/Billing[1]/Invoices[3]/Periods`. **The consequence is about the instrument, not the output:** every `adapter/laws` differential compares this projection, so an engine attributing such a finding to the wrong row would compare **equal**. `adapter.laws.NestedOverLimitAbsorptionDiffTest.theKernelAddressesEachDescendantRowDistinctlyWhereOurFormattedAddressCollapsesThem` pins the Kernel's own coordinate lists across both codegen strategies so the class is covered meanwhile.

  **Corrected 2026-08-31 — the PUBLISHED surfaces are not affected, and the first version of this row said they were.** `A12Pointers.canonicalExactForm` and `KernelRuntimeProbe.address` both prefer `A12PointerFormat.render(toExactPointer())` and fall back to the house form only when a pointer carries **no** repetition indexes. That canonical form is **faithful** on exactly the case above — measured: `[1,3,1]`→`Billing/Invoices[3]/Periods`, `[1,3,2]`→`…/Periods[2]`, `[1,3,3]`→`…/Periods[3]`, three distinct strings. So the kernel-probe artifact and dmtool's message addresses distinguish the rows today; a12-kernel-lean established the artifact half independently by enumerating all 61 retained artifacts (238 engine records per kernel engine, no interpreter engine in any) after this row claimed otherwise. The claim was asserted from a call site I had measured — the differential's helper — without opening the two that publish, which is the "unaffected" register the oracle rules name.

  **What that leaves, and it changes the fix.** The affected surfaces are the ones that compare: the `adapter/laws` differentials, and the **23 committed corpus case files** that store house-form addresses (`/Order[1]/StockOnHand`). Since the projection is tool-owned and internal by its own contract, the better fix is probably not to change it at all but to give the differential a faithful comparison key — the corpus keeps its spelling, no published string moves, and the blind spot closes. **a12-kernel-lean asked for additive raw coordinates on the probe artifact** before its own correction landed; the premise of that request (that the artifact cannot distinguish the rows) is what the correction removes, so it is on hold pending their re-read rather than scheduled. Related: [IAG11](INTERPRETER-GAP-ID-REGISTRY.md#iag11), [IAG15](INTERPRETER-GAP-ID-REGISTRY.md#iag15).

## 2. Deferred / ongoing-incremental (recorded with status; detail in [`INTERPRETER-FINDINGS.md`](INTERPRETER-FINDINGS.md))

Two kinds live here when present: a **deferred** item (parked or owner-accepted until its re-open trigger flips) and an **ongoing as-touched** refactor. A deferred item may be a safely guarded capability residual; it is not a silent semantic mismatch. A fully shipped item is deleted (its `IF<n>` finding + git are the record).

- **IG143 — a HAND-BUILT interpreter document is a route hybrid, so two cross-route laws are ungated (opened 2026-08-28, deferred).** `Document.field(path, text)` is the test-only construction route (the public ingress is `readDocument`/`seedDocument` — enumerated from the ABI golden in [IF313](INTERPRETER-FINDINGS.md#if313)). It leaves `numberIdentity` null, so **NUMBER behaves like A12's V1 String route** (always changed), while every other kind compares stored text and so behaves like the **typed** route. That hybrid is not a defect in shipped behaviour, but it means a law comparing a kernel V1 applied state against a hand-built interpreter one is route-mismatched for Number and route-matched for the rest.

  **Two sites, both latently safe today:** `adapter.laws.ComputedTimeTargetDiffTest` and `AppliedCellStateDiffTest` (kernel apply + `newDocument()`, no `readDocument`). Neither seeds a computed cell with its own computed value, which is the only input that separates the routes, so no assertion is currently wrong. `CrossRouteGateCensusGuardTest` deliberately scopes itself to the TYPED transport and says so, rather than pretending to cover these.

  **Why deferred rather than gated now.** `CrossRouteSourceGate.requireRouteAgnostic` compares the V1 changed set against the TYPED retained set; gating the hand-built sites needs a third comparand, and the honest fix is upstream — decide whether a hand-built document should model the V1 route (populate no identity for any kind) or the typed route (populate identity for Number too) and make it coherent. Choosing while two laws depend on the current hybrid is what the convergence gate says not to do inside a slice that already grew twice. **Re-open trigger:** a hand-built cross-route law seeds a source-identical cell, or the harness's document construction is unified. **What would settle it:** measure a source-identical NUMBER and a source-identical DATE through all three routes and pick the profile `Document.field` should present.

- **IG141 — the interpreter keeps DateRange formats declaration-local while kernel codegen shares an order-dependent first format (opened and deferred 2026-08-24).** [KF210](KERNEL-FINDINGS.md#kf210) and [IF311](INTERPRETER-FINDINGS.md#if311) pin the discriminator: placing interpreted `dd.MM` declarations before interpreted `MM` declarations makes both kernel strategies admit `11/02` and store `01.11-01.02`; reversing only those declaration blocks rejects the wrap and keeps ordered `03/10`. The interpreter gives the second, declaration-local result under both orders.

  **Why it is deferred rather than copied from the reported model.** The proposed field-local correction is falsified, and the actual contract belongs to a cross-model shared-format mechanism. Implementing first-wins behavior from one equivalence class would silently widen the slice to every DateRange format, separator, interpretation direction, declaration order, formal check, computation source and target, and JSON conversion path. The convergence gate applies because the acceptance denominator changed during reconciliation. **Re-open trigger:** either the pinned kernel fixes the shared-format defect, or a bounded conformance decision explicitly chooses to mirror it. **What would settle it:** enumerate the shared-format equivalence classes from `IDateRangeType.getFormatOfDateRange` and `CodeGenDateRangeTypeImpl`, then run order-swapped dynamic/Java controls across formal validation, direct reads, and computation input/output before choosing the interpreter policy.
