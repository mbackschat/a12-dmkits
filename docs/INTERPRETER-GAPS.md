# interpreter — gaps & open issues

> **What this is** — the interpreter's peer of [`DEV-API-GAPS.md`](DEV-API-GAPS.md) and [`FEATURE-GAPS.md`](FEATURE-GAPS.md): the single tracking surface for **open `:interpreter` gaps, deferred items, and to-fix issues**. It exists so open work is easy to **track, report, and pick up** — and so [`INTERPRETER-FINDINGS.md`](INTERPRETER-FINDINGS.md) can be what a findings doc should be: **settled, verified knowhow** you read to warm up and not re-investigate (like `KERNEL-FINDINGS.md`), never a backlog of dispositions ("open / to fix / deferred"). Per the CLAUDE.md *"rationale is timeless; a disposition is status"* rule — the findings hold the timeless fact, this ledger holds the live status.
>
> **The lifecycle.** A gap is born here with an `IG<n>` code under the section matching its status (§1 open / §2 deferred / §3 out-of-scope). When it ships, three things happen **in the fix's own commit**: (1) its **rationale graduates to a numbered `IF<n>` finding** in [`INTERPRETER-FINDINGS.md`](INTERPRETER-FINDINGS.md) — that finding notes it "graduated from IGn"; (2) any code/test comment citing `IGn` is **repointed to `IFn`**; (3) the gap's row is **deleted from this ledger**. **There is no "fixed/shipped" section — we don't record fixed gaps.** A fixed gap is no longer a gap; **git is the history of *when/what* was fixed, and the `IFn` finding is the *why*** — a hand-kept "shipped" list would only duplicate both and rot. So this ledger only ever lists **live, unfinished work** (the already-shipped IF20-per-cell / IF21 / IF23 / IF24 / IF25 live as findings, not here). A **deferred** gap stays in §2 with its re-open trigger, and an **ongoing as-touched** refactor stays in §2 with its remaining-work note (it is progressing in increments, not parked — its shipped parts graduate to its `IF<n>` finding while the row stays until *all* of it lands); the technical detail of each gap lives in its cited `IF<n>` finding (the knowhow), this ledger holds only *what's left to do and why*.
>
> **Section invariant (the placement rule):** every section holds exactly one **live** status — **§1 = open, §2 = deferred / ongoing-incremental, §3 = out-of-scope**. A FULLY-shipped/graduated entry belongs in **none** of them: completing it *deletes* its row (see the lifecycle). So §1 reads "(none)" whenever nothing is open, and a fully-FIXED entry **anywhere** in this ledger is a bug in *this doc* — git already records the fix. (A partially-shipped *ongoing* refactor in §2 is not "fixed" — it stays until all of it lands.)
>
> **Scope.** `:interpreter` only — the kernel-free Kotlin evaluator (parser, evaluation semantics, model loader, the differential/perf harnesses' interpreter side). dmkit (rulekit/modelkit/edit) authoring gaps go to [`DEV-API-GAPS.md`](DEV-API-GAPS.md); kernel-coverage classification stays in the MVK / RT-semantics / grammar ledgers.

## 1. Open (to fix)

- **IG68 — standalone commonMain has no complete workspace/prepared-model assembler (graduated residual of IG67 / IF122, broadened 2026-07-19; activated 2026-07-26; implementation and dmtool dogfooding complete through R2.11, browser gate remains).** `ModelLoader` handles only one already-expanded, self-contained, name-path-keyed model. It cannot mount `modelReferences`/includes, merge imported typedefs and inline effective types, normalize opaque ids to name paths, or remap included references; recognized raw residue does **not** load silently — an unexpanded include, unresolved `TypeDefType`, or opaque element id is rejected loudly (IF145). R2.2–R2.11 now provide and dogfood one original commonMain preparation pipeline over a bounded immutable workspace, constructible from an initial source map or collected on demand through an asynchronous exact-id `ModelSourceProvider`: it implements all four transforms, the assembler-only expanded artifact, structured acquisition/preparation diagnostics, JVM/Node Java-reader/Kernel parity, immutable prepared ownership, the minimum evaluation façade, Kotlin suspension, an unexported Promise/`AbortSignal` bridge, Java `CompletionStage` acquisition without platform types in `commonMain`, and dmtool `model expand` plus runtime preparation. Collection requests only one snapshot-consistent discovered closure, loads each id at most once, verifies identity and SHA-256 before following edges, freezes admitted bytes, enforces acquisition and aggregate limits, propagates typed no-retry cancellation/failures, and retains only sanitized provenance. The row remains open only for R4.2's real-browser workspace/parity gate; that browser evidence graduates it. The public contract is specified in [INTERPRETER-API-PROPOSAL](INTERPRETER-API-PROPOSAL.md) §4.1 and the release gate in [INTERPRETER-RELEASE-PROPOSAL](INTERPRETER-RELEASE-PROPOSAL.md).

- **IG85 — implementation and local delivery proof are complete; anonymous public-GitHub consumption remains (delivery gap, found 2026-07-19; activated 2026-07-26; R3.1–R3.3 completed 2026-07-26).** The interpreter has an independent SemVer source; root/JVM/JS KMP publications in the future GitHub Pages Maven layout; the functional `@mbackschat/a12-interpreter` tarball with generated `.d.ts`; reviewed Kotlin/JVM/KLIB and TypeScript ABI locks; exact npm/Maven package allowlists; dependency, secret, and checksum gates; and fresh standalone Kotlin/JVM, Kotlin/JS, and strict TypeScript consumers. The Kotlin/JS consumer proves the published KLIB contributes its transitive `big.js:6.2.2` npm dependency before executing real decimal validation/computation. IF173 protocol v2 measures the actual npm tarball and clean staged Maven repository alongside the existing JVM/KLIB/native bases; an older revision that predates a delivery surface records `NOT_AVAILABLE_IN_BASELINE` and receives no fictional numeric delta. The row remains open only until R8 consumes the release assets and Pages Maven tree anonymously from the new public GitHub repository.

- **IG86 — browser packaging smoke is complete; conformance and first-answer qualification remain (activated 2026-07-26; prior deferral recorded in IF138; R4.1 completed 2026-07-26).** `:interpreter` now registers both `nodejs()` and `browser()` environments. A fresh Vite consumer installs the actual `@mbackschat/a12-interpreter` tarball, bundles it under `/a12-interpreter-releases/showcase/`, fetches its model relative to that Pages base, and executes preparation, validation, and decimal computation in system Chrome through a deadline-bounded `playwright-core` harness. The packed JavaScript remains free of Node-only imports. Decimal and regex host semantics are complete under IF163/IF164; the regex translator and registry use the browser-safe ES2018 baseline. R4.2 still must replay the portable conformance and raw-workspace subsets in a real browser, retain the host-sensitive decimal/regex locks there, and give browser first-answer its own explicitly scoped owner-ratified bar. Browser support remains unclaimed until those gates pass; Node becomes a CI proxy only after equivalence is demonstrated.

New semantic or performance defects belong here only while they have actionable work and a defined completion gate.

## 2. Deferred / ongoing-incremental (recorded with status; detail in [`INTERPRETER-FINDINGS.md`](INTERPRETER-FINDINGS.md))

Two kinds live here when present: a **deferred** item (parked or owner-accepted until its re-open trigger flips) and an **ongoing as-touched** refactor. A deferred item may be a safely guarded capability residual; it is not a silent semantic mismatch. A fully shipped item is deleted (its `IF<n>` finding + git are the record).

- **IG83 — Route A: general portable timezone-id support (owner-accepted deferred capability; Route B completed as IF155/IF165/IF166).** The enforced evaluator contract supports exact `{UTC, GMT, Europe/Berlin}`; Berlin uses the independently locked legacy-`java.util.TimeZone` history, explicit invalid ids fail as configuration errors, and known kernel-legal zones outside the set fail with the precise supported-scope diagnostic. The kernel accepts a wider Java `TimeZone` id domain, so this remains an honest product limit, not full timezone parity. **Re-open trigger:** a real consumer needs a non-Berlin zone or a publication wave promises full timezone parity. Then build one portable, deterministically versioned tzdb for JVM + JS and pin its version relationship to the kernel's JDK tzdb.
